## 0. UI 选型（先定死，换库成本极高）

| 方案 | 成熟度 | AI 友好度 | 结论 |
|---|---|---|---|
| **Ant Design Vue 4** | ★★★★★ 企业级组件最全（表格/表单/树/穿梭框/描述列表） | ★★★★★ API 规整、语料多 | **采用** |
| Element Plus 2 | ★★★★★ 国内使用最广，若依系团队迁移最顺 | ★★★★★ | 备选（团队强偏好时） |
| Vben Admin 5 | ★★★★ 成熟中后台壳（monorepo/动态路由/多页签/主题） | ★★ 抽象层厚，AI 改错概率高 | **只作参考实现，不 fork** |
| Naive UI | ★★★★ 类型最好、体积小 | ★★★ 语料偏少 | 不采用 |
| Arco Design Vue | ★★★ 组件较全 | ★★★ | 不采用 |

**为什么选 Ant Design Vue：**

1. **组件覆盖最全**：Table 支持虚拟滚动、可编辑单元格、树形数据、固定列，管理后台 80% 的复杂度都在这。
2. **设计语言统一**：几十个产品页面不会"越长越花"，对 AI 批量生成页面尤其重要——它只需要照一套规范填。
3. **TypeScript 类型完整**：AI 写错 props 编译期就红，不用等运行时。
4. **语料密度高**：中文文档 + 大量开源项目，AI 生成准确率明显高于小众库。

**为什么不直接 fork Vben Admin：**

- Vben 5 是优秀的壳，但抽象层厚（适配器 + hooks 包装 + 多层 provider）。改一个路由要穿 4 层文件，**AI 容易改错且难以自证**。
- 我们的壳只需要：布局 + 动态路由 + 权限 + 页签 + 主题 + i18n，自研约 3000 行，AI 完全可控。
- **借鉴其交互与目录设计，不复制其抽象。**

**换库成本控制**：业务代码只依赖 `@admin/ui`，换库只改这一层（预计 1–2 人周）。**永远不要在业务页面直接 import 组件库。**

### 0.1 Vue 的三条硬约束（AI 质量红线）

| 约束 | 说明 | 强制手段 |
|---|---|---|
| **只允许 `<script setup lang="ts">`** | 禁止 Options API、禁止两种写法混用。AI 混写是 Vue 项目最大的质量漏洞 | eslint `vue/component-api-style: ['error', ['script-setup']]` |
| **`vue-tsc --strict` 必过** | 模板里的类型错误必须编译期拦截，不能靠运行时 | CI `vue-tsc --noEmit`，`noImplicitAny: true` |
| **通用组件源码入仓** | ProTable / SchemaForm 等自研组件源码放在 `packages/ui`，不引黑盒 npm 包 | 代码评审 + 依赖白名单 |

**路线图**：跟踪 **Vue Vapor 模式**（去虚拟 DOM，API 不变）。稳定后作为构建开关切换，不改业务代码。

> 多端策略（Web / Tauri 桌面 / Flutter 移动）见 `08-多端架构（Web+Tauri+Flutter）.md`。

## 2. 分层（简化版 Feature-Sliced）

| 层 | 目录 | 内容 | 依赖 |
|---|---|---|---|
| `app` | `src/app` | 启动、路由装配、全局 provider | 全部 |
| `pages` | `views/**` | 路由页面（编排层，薄） | features / entities |
| `features` | `src/features/*` | 一个业务动作（如"创建客户"弹窗） | entities / shared |
| `entities` | `src/entities/*` | 领域模型、API、类型、状态 | shared |
| `shared` | `packages/*` | 无业务语义的通用能力 | 无 |

**规则**：只能向下依赖，同层不互相引用；`pages` 不写业务逻辑（> 50 行就该抽 feature）。

## 3. 路由与权限

### 3.1 路由来源

```
静态路由（壳）：/login、/403、/404、/redirect、布局容器
动态路由（后端下发）：登录后 GET /api/system/menus/routes
  → 菜单树 [{ path, name, component, meta: { title, icon, perm, keepAlive, hidden, cache } }]
  → 前端 componentMap 映射到真实组件
  → router.addRoute() 逐条注册
```

```ts
// plugins.ts —— 构建期聚合，类型安全
const modules = import.meta.glob('../../plugins-web/*/plugin.ts', { eager: true });
export const pluginRoutes = Object.values(modules).flatMap((m: any) => m.default.routes);
export const componentMap: Record<string, () => Promise<any>> = Object.fromEntries(
  pluginRoutes.map((r: any) => [r.name, r.component]),
);
```

```ts
// router/guard.ts
router.beforeEach(async (to) => {
  if (to.meta.public) return true;
  if (!session.isLoggedIn) return { path: '/login', query: { redirect: to.fullPath } };
  if (!session.routesLoaded) {
    await session.loadProfile();      // 用户信息 + 权限点 + 菜单
    await registerDynamicRoutes();     // addRoute
    return { ...to, replace: true };   // 重新匹配
  }
  if (to.meta.perm && !perm.has(to.meta.perm)) return '/403';
  return true;
});
```

### 3.2 四层权限

| 层 | 控制点 | 实现 |
|---|---|---|
| 路由级 | 页面能否进入 | 动态路由 + `meta.perm` 守卫 |
| 按钮级 | 按钮是否渲染 | `v-perm="'crm:customer:add'"` 指令（无权限直接移除节点） |
| 字段级 | 列/表单项是否可见 | `useFieldPerm()` + 脱敏展示组件 |
| 数据级 | 能看到哪些行 | 后端负责，前端只展示（**永不在前端做数据过滤**） |

```vue
<a-button v-perm="'crm:customer:add'" type="primary" @click="openCreate">新增</a-button>
```

> **安全红线**：前端权限只影响"看不看得见"，不是安全边界。所有校验必须在后端重做。

### 3.3 页签（多页签）与缓存

- 页签状态存 Pinia（`tabs` store）：`{path, title, closable, keepAlive}`。
- `keep-alive` 用 `include` 匹配组件 `name`，需与路由 `name` 一致（约定强制）。
- 关闭页签 → 从 `keepAlive` 列表移除 → 组件销毁 → 清理订阅。
- 刷新当前页 → 先移除缓存再 `router.replace`。

### 3.4 特殊路由

| 类型 | 处理 |
|---|---|
| 外链 | `meta.link` + 新窗口打开，不进路由表 |
| iframe 内嵌 | `meta.iframe = true`，用 `IframeView` 渲染（`sandbox` 属性） |
| 详情页 | 扁平化路由 `/crm/customer/detail/:id`，避免多级嵌套过深 |
| 无权限页 | `/403` 独立页面，不占页签 |

## 4. 状态管理

### 4.1 两类状态，严格分开

| 类型 | 存放 | 例 |
|---|---|---|
| **服务端状态** | `@tanstack/vue-query` | 列表、详情、字典、统计 |
| **客户端状态** | 当前使用 Vue ref；复杂状态可按既定架构演进 | 当前用户、权限点、界面状态；Pinia 为目标方案 |

**反模式**：把接口数据存进 Pinia 再手动同步 —— 缓存失效、竞态、内存泄漏全来了。

**当前实现（2026-11-10）**：`api/query-client.ts` 导出共享 `queryClient`，`main.ts` 注册 `VueQueryPlugin`；
默认 `staleTime: 30s`、关闭窗口聚焦重取、查询 `retry: 1`。退出/重新登录调用 `clearSession()`，
同时清空身份、查询及 mutation 缓存，避免下一账号复用上一租户的数据；在途 `/me` 通过代次校验禁止旧身份回填。
`PostsView`、`DeptView`、`ConfigsView`、`FilesView`、`ExportsView`、`NoticesView`、`SessionsView`、`RolesView`、`UsersView`、`TenantsView`、`AuditLogTable`、`ContractsView`、`PaymentsView`、`CustomersView`、`ContactsView`、`OpportunitiesView`、`CustomerDetailView`、`ContractDetailView`、`OpportunityDetailView`、`DashboardView`、`PipelineView`、`HomeView`、`DictsView`、`MenusView` 已完成迁移（`useQuery` + `useMutation` + `invalidateQueries`），CRM 全部页面与其余列表页均已覆盖。
决策见 `docs/adr/0003-服务端数据使用-vue-query.md`。

### 4.2 Query Key 规范

```ts
// 层级化 key，便于批量失效
['crm', 'customer', 'list', query]        // 列表
['crm', 'customer', 'detail', id]         // 详情
['sys', 'dict', 'customer_status']        // 字典

// 失效策略
queryClient.invalidateQueries({ queryKey: ['crm', 'customer'] });  // 该域全部失效
```

| 配置 | 值 | 理由 |
|---|---|---|
| `staleTime` | 默认 30s；当前字典为 Infinity | 字典在缓存存在期间复用，显式清理/身份切换后重新加载 |
| `gcTime` | 5min | 内存回收 |
| `retry` | 1 次（GET） | 写操作不重试（防重复提交） |
| `refetchOnWindowFocus` | false | 后台系统不需要 |

### 4.3 字典与枚举

```ts
// 当前按需查询：items 是响应式字典项，labelOf 找不到时返回原值
const { items, loading, labelOf } = useDict('customer_status');
```

- 当前入口为 `src/composables/useDict.ts`，查询键为 `['system-dict', code]`，使用共享 vue-query 缓存，不写 localStorage、不比对字典版本。
- `loadDict(code)` 复用相同查询配置并去重，`clearDictCache()` 删除字典查询；`clearSession()` 清理全部服务端缓存。
- 查询向 `request()` 传递 AbortSignal，清理后的旧请求不能把上一个身份的字典写回缓存。
- 字典版本同步、批量预加载与统一 `DictTag` 为演进目标；当前通过字典项与 `labelOf` 渲染，避免硬编码状态文案。

## 5. 请求层（当前 `src/api/`，目标 `packages/sdk`）

### 5.1 统一封装

**当前入口**是 `src/api/client.ts` 的 `request<T>(path, init)` 与 `http.get/post/put/patch/delete`，基于 fetch：

- 统一携带 HttpOnly Cookie；成功解包 `{data}`，204 返回 undefined；成功体缺少 data 时显式报错。
- Headers、元组数组和普通对象三种请求头均能保留；字符串请求体默认 JSON，FormData 由浏览器生成 multipart boundary。
- problem 错误保留业务码、文案和 HTTP 状态；代理返回 HTML、纯文本或无响应体时返回带 HTTP 状态的 ApiError，不把代理 HTML 展示给用户。
- 原样转交 AbortSignal；网络异常由调用页面处理。客户端本身没有刷新令牌、自动重放或全局 503 重试。

以下 RequestConfig/createClient 为 SDK 目标设计，当前调用应使用上述真实入口：

```ts
export interface RequestConfig {
  url: string; method?: Method; params?: any; data?: any;
  silent?: boolean;              // 不弹全局错误
  raw?: boolean;                 // 返回完整响应（下载/文件）
  timeout?: number;
  retry?: number;
}

const http = createClient({
  baseURL: import.meta.env.VITE_API_BASE,
  timeout: 30_000,
  withCredentials: true,         // Cookie 会话必需
});
```

### 5.2 拦截器职责链

下表为目标职责。当前路由守卫在 `/api/auth/me` 失败时跳登录；页面按权限路由到 403；
请求客户端统一抛出 ApiError，由页面处理提示。双令牌与单飞 refresh 尚未实现，不能据此调用刷新接口。

| 阶段 | 处理 |
|---|---|
| 请求前 | 注入 `X-Request-Id`、`Accept-Language`、`X-Tenant-Id`（多租户切换时）。**不需要** `X-CSRF-Token`：当前 CSRF 防护由后端校验 `Sec-Fetch-Site` / `Origin` 完成 |
| 响应 2xx | 解包 `{data}`，返回 `data` |
| 401 | **单飞刷新**：并发请求排队等待同一个 refresh，刷新成功后重放；失败则清会话跳登录 |
| 403 | 提示"无权限"，跳 403 页（不弹 toast 堆叠） |
| 422 | 交给表单展示字段错误（返回 `errors[]`） |
| 429 | 目标读取 `Retry-After` 并倒计时；通用错误为 5s，登录限流为 60s；当前客户端不自动重试 |
| 503 | 后端过载/停机/数据库不可用，读 `Retry-After` 后**指数退避重试 ≤2 次**；仍失败则提示"服务繁忙" |
| 5xx | 全局错误提示 + 上报（含 `traceId`，可复制反馈） |
| 网络异常 | "网络异常，请检查连接"，支持重试按钮 |

> 429 与 503 的差异要体现在文案上：429 是"操作太频繁"（用户可等待），
> 503 是"服务暂时繁忙"（不是用户的错，不要显示成操作失败）。

```ts
// 目标示意，尚未实现：401 单飞刷新需先有后端 Refresh 契约
let refreshing: Promise<void> | null = null;
async function onUnauthorized() {
  refreshing ??= doRefresh().finally(() => { refreshing = null; });
  await refreshing;
}
```

## 7. 组件体系

### 7.1 `@admin/ui` 封装原则

| 原则 | 说明 |
|---|---|
| 唯一出口 | 业务代码禁止直接 `import { Table } from 'ant-design-vue'`（eslint 限制） |
| 只做增强，不做抽象泄漏 | 保留 AD 的 props/事件透传（`v-bind="$attrs"`） |
| 主题由 Token 驱动 | 颜色/圆角/间距/字号全部读 CSS 变量，不写死 |
| 复杂组件单独立项 | ProTable、SchemaForm、DictTag、FileUpload、OrgPicker 等 |

### 7.2 Design Token

```css
:root {
  --ad-color-primary: #1677ff;
  --ad-radius-md: 6px;
  --ad-space-md: 16px;
  --ad-font-size-body: 14px;
  --ad-header-height: 48px;
}
[data-theme='dark'] { --ad-color-bg: #141414; /* ... */ }
```

- 支持：亮/暗、紧凑/宽松、品牌色替换（客户定制只改一个 CSS 文件）。
- 字号与间距遵循 4px 栅格。

### 7.4 SchemaForm（JSON Schema 驱动）

## 10. 微前端（插件前端演进）

### 10.1 两阶段

| 阶段 | 方式 | 适用 |
|---|---|---|
| **一期（默认）** | 构建期聚合（`import.meta.glob`） | 自有团队，统一发布 |
| **二期（按需）** | Module Federation 运行时加载 | 客户现场装插件、插件独立发布 |

### 10.2 MF 配置要点

```ts
// 远程插件 vite.config.ts
federation({
  name: 'crm_web',
  filename: 'remoteEntry.js',
  exposes: { './plugin': './src/plugin.ts' },
  shared: { vue: { singleton: true }, 'vue-router': { singleton: true }, pinia: { singleton: true } },
});
```

| 问题 | 方案 |
|---|---|
| 双 Vue 实例 | `shared.singleton = true` + `requiredVersion` 严格匹配 |
| 样式污染 | 插件样式加前缀 `[data-plugin="crm"]`；宿主提供 `reset` 隔离 |
| 路由冲突 | 插件路由必须带 `/{pluginId}` 前缀，注册前校验重复 |
| 状态共享 | 只通过 `sdk` 暴露的 `useSession/usePerm/useDict`，禁止直接访问宿主 store |
| 版本不兼容 | 宿主维护插件清单 `{id, entry, version, kernelRange}`，启动校验 |
| 加载失败 | 降级：菜单置灰 + 提示"插件加载失败"，不影响其他模块 |
| 安全 | 只加载**白名单域名**的 remoteEntry，校验 SRI（可选） |

### 10.3 插件清单

```json
{
  "id": "crm", "name": "客户管理", "version": "1.4.2",
  "kernelRange": ">=1.2.0 <2.0.0",
  "entry": "https://cdn.example.com/crm/1.4.2/remoteEntry.js",
  "routes": ["/crm/*"], "permissions": ["crm:customer:list"]
}
```

## 13. 安全

| 风险 | 防护 |
|---|---|
| XSS | 禁 `v-html`（除白名单富文本组件，接入 DOMPurify）；CSP 头由后端下发 |
| CSP 兼容 | 后端 CSP 为 `script-src 'self'`、`connect-src 'self'`：**禁止内联脚本**、禁止直连第三方 API/WebSocket；需要新域名时先改 `kernel::security` 再开发 |
| CSRF | 提交来源由后端中间件校验（`Sec-Fetch-Site` + `Origin`/`Host`），前端无需额外 token |
| 会话 | HttpOnly Cookie，JS 读不到；前端只依赖 `/api/auth/me` 判断登录态 |
| 点击劫持 | `X-Frame-Options: DENY`（除允许内嵌的页面） |
| 敏感信息 | 不在 localStorage 存 token；不把密钥写进前端 env |
| 依赖供应链 | `pnpm audit` + `lockfile` 锁定 + 定期升级；禁用 `postinstall` 脚本（`ignore-scripts`） |
| 富文本 | 后端 sanitize + 前端白名单渲染 |
| 文件预览 | iframe `sandbox` + 独立域名，禁止同源 |
| 调试入口 | 生产构建移除 `console`、`debugger`、sourcemap（或上传私有源） |

## 15. 前端反模式

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 业务代码直接 import ant-design-vue | 换库成本爆炸 | 只经 `@admin/ui` |
| 接口数据塞进 Pinia | 缓存/竞态/泄漏 | vue-query 管服务端状态 |

| 用 `any` 糊过去 | 类型形同虚设 | `unknown` + 类型守卫 |

## 附录 A · 前端框架选型对比（决策记录）

评估维度：**训练语料密度（AI 一次通过率）、类型安全、企业组件库、架构约束力、多端能力、迁移成本**。

| 框架 | 语料密度 | 类型安全 | 企业组件库 | 架构约束力 | 多端 | 迁移成本 | 综合 |
|---|---|---|---|---|---|---|---|
| **Vue 3.5** | ★★★★★（中文最强） | ★★★★ | ★★★★★ | ★★★ | ★★★ | 低 | **采用（管理后台）** |
| React 19 | ★★★★★ | ★★★★★ (TSX) | ★★★★★ | ★★☆ 自由度太高 | ★★★★★ (RN) | 中 | 备选（C 端/新工具型产品） |
| Angular 20 | ★★★★ | ★★★★★ | ★★★★ | ★★★★★ | ★★ | 高 | 大团队/十年期项目 |
| Svelte 5 | ★★★ | ★★★ | ★★★ | ★★★ | ★★ | 中 | 不采用（语料少，4/5 语法易混） |
| SolidJS | ★★ | ★★★★ | ★★ | ★★ | ★ | 高 | 不采用 |
| Leptos / Dioxus (Rust) | ★ | ★★★★ | ★ | ★★★★ | ★★★ | 极高 | 暂不用于生产后台 |

### A.1 为什么最终选 Vue

1. **若依系团队迁移成本最低**，国内招聘池最大。
2. Ant Design Vue 的表格/表单深度最匹配管理后台（80% 复杂度在这）。
3. 中文语料密度最高，AI 生成的中文业务代码更"像样"。
4. 生态稳定，Vapor 模式提供清晰的性能演进路径。

### A.2 什么情况下应该换 React

- 新开产品中 **50% 以上是 C 端/多端**（社区、门户、营销、需要 RN 复用）。
- 团队已有 React 经验，或需要大量开源组件（shadcn 生态）。
- 需要 React Compiler 自动 memo 来规避性能问题。

> 但**不要双框架并行**：双设计系统 + 双组件库 + 双招聘要求，成本远大于 10–15% 的 AI 通过率差异。

### A.3 什么情况下考虑 Angular

- 前端团队 ≥ 50 人，需要强约束保证一致性。
- 项目生命周期 ≥ 10 年，且合规审计要求高（金融/政企）。
- 团队能接受 RxJS 的学习曲线（对 AI 不友好，需额外约束）。

### A.4 Rust-WASM 前端（Leptos / Dioxus）

| 项 | 现状 |
|---|---|
| 包体积 | WASM 起步 300KB+ |
| 组件库 | 几乎没有企业级表格/表单 |
| AI 语料 | 接近零 |
| 招聘 | 极难 |

**唯一推荐场景**：IM 桌面端用 **Tauri 2**（Rust 壳 + 复用 Web 前端），而不是用 Rust 写 UI。详见 `08-多端架构`。

## 前端插件注册表（M4）

### 为什么先做注册表，不直接拆 pnpm 包

独立包要处理依赖版本、构建产物、类型共享、发布流程，成本高。
注册表已经实现核心目标：**新增业务插件只改一个目录 + 一行注册**。

### 用法

```ts
// src/plugins/crm/index.ts
export const crmPlugin: FrontendPlugin = {
  id: 'crm',
  routes: [
    { path: 'crm/customers', name: 'crm-customers', component: () => import('./CustomersView.vue') },
  ],
};
```

```ts
// src/plugins/index.ts
export const frontendPlugins: FrontendPlugin[] = [crmPlugin];
```

路由表通过 `...frontendPlugins.flatMap((p) => p.routes)` 自动展开。

### 约定

1. 插件目录内不引用其他插件的组件；
2. 可以引用内核能力（`api/client`、`stores/session`、`v-perm`）；
3. 路由 name 加插件前缀，避免跨插件重名；
4. 前端 path 必须与后端 `Plugin::menus()` 声明的 path 一致。

### 后续演进

需要独立发版或按需加载时，把 `src/plugins/<id>` 提升为 `plugins-web/<id>-web` 包，
注册表改为动态导入即可，页面代码不用改。
