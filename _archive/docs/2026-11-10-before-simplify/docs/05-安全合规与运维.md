# 05 · 安全合规与运维交付

> 目标：等保三级可过、私有化能交、SaaS 能扛｜原则：**默认拒绝、最小权限、可审计、可回滚**

---

## 1. 安全基线

### 1.1 身份与会话

下表为安全目标，不能作为当前已交付能力清单。当前实际使用数据库 Cookie 会话（默认 8 小时），
没有 Access/Refresh 轮换、空闲超时、MFA 或敏感操作二次票据；登录 IP 限流默认 60 次/分钟，
账号锁定默认 5 次失败锁 15 分钟，租户策略可覆盖。单端替换已事务化，但其他实例会话缓存最长 30 秒后失效。
退出时数据库撤销失败不会返回假成功；基础回归证据见 [基础功能报告](./基础功能分析与加固-2026-11-10.md)。

| 项 | 要求 |
|---|---|
| 密码存储 | Argon2id（m=19456, t=2, p=1），禁止 MD5/SHA1/bcrypt 低轮次 |
| 密码策略 | ≥ 10 位，大小写+数字+符号至少三类，90 天更换，禁 5 次重用 |
| 登录失败 | 5 次锁 15 分钟，指数退避；同 IP 10 次/分钟限流 |
| 账号枚举防护 | 用户不存在 / 已停用 / 已锁定 也必须付出等价的 Argon2 成本（时序对齐） |
| 客户端 IP | 只信 TCP 对端；仅当对端在 `trusted_proxies` 内才采信 `X-Forwarded-For`（从右往左取第一个不可信地址） |
| 会话 | HttpOnly + Secure + SameSite；Access 15min / Refresh 7d 轮换 |
| 并发登录 | 可配置单端/多端；"踢下线"立即生效 |
| 空闲超时 | 30 分钟 |
| MFA | TOTP 可选强制（管理员必开），恢复码一次性 |
| 敏感操作 | 二次认证票据（5 分钟有效）：改密、改权限、批量导出 |

### 1.2 传输与存储

| 项 | 要求 |
|---|---|
| 传输 | 全站 HTTPS（TLS 1.2+），HSTS `max-age=31536000`，禁用弱套件 |
| 静态加密 | 数据库磁盘加密（LUKS/云盘加密）；备份加密（SSE-KMS） |
| 字段加密 | 身份证/银行卡等用 `pgcrypto` 或应用层 AES-GCM，密钥存 KMS/Vault |
| 密钥管理 | 禁止硬编码；启动时从环境变量/Secret 注入；支持轮换 |
| 日志脱敏 | 手机号/身份证/密码/Token 一律脱敏后落盘 |

### 1.3 依赖与供应链

```bash
cargo audit                    # 已知漏洞
cargo deny check licenses      # 许可证合规（禁 GPL 传染到闭源交付）
cargo deny check bans          # 禁用 crate（如 openssl 换 rustls）
cargo cyclonedx                # 生成 SBOM（交付必带）
pnpm audit --prod
```

| 项 | 要求 |
|---|---|
| 锁文件 | `Cargo.lock`、`pnpm-lock.yaml` 必须入库 |
| 依赖更新 | 每月例行，安全公告 24h 内评估 |
| 构建可复现 | 固定工具链（`rust-toolchain.toml`）、固定基础镜像 digest |
| 制品签名 | 镜像签名（cosign）+ SBOM 随包交付 |

## 2. OWASP Top 10 → 本架构对策

| 风险 | 具体表现 | 对策（落地位置） |
|---|---|---|
| A01 越权 | 改 URL 里的 id 看别人数据 | 对象级授权（repo 只提供 `*_scoped`）+ RLS 兜底，越权返回 404 |
| A02 加密失效 | 明文存密码、HTTP 传输 | Argon2id、全站 TLS、字段加密 |
| A03 注入 | SQL/命令/模板注入 | sqlx 绑定参数、禁用字符串拼接、排序白名单、无 shell 调用 |
| A04 不安全设计 | 无限流、无配额 | 分桶限流、租户配额、幂等键 |
| A05 配置错误 | 生产开 debug、默认密码 | 配置校验启动即失败、强制改初始密码、CSP/HSTS |
| A06 脆弱组件 | 老版本依赖 | cargo audit/deny、月度升级 |
| A07 认证失效 | 会话固定、弱口令 | 登录后换 session id、密码策略、MFA |
| A08 数据完整性 | 供应链投毒 | 锁文件、签名、SBOM、私有 registry |
| A09 日志监控不足 | 出事查不到 | 审计日志、告警、trace_id |
| A10 SSRF | 用户可控 URL 被服务端请求 | 出站域名白名单、禁内网 IP、禁用重定向 |

### 2.1 SSRF 防护（容易漏）

```rust
// 回调/Webhook/图片抓取等场景：解析后校验 IP 段
let ip = resolve(host).await?;
if ip.is_loopback() || ip.is_private() || ip.is_link_local() || ip.is_unspecified() {
    return Err(AppError::Forbidden);   // 拒绝 127.0.0.0/8、10/8、172.16/12、192.168/16、169.254/16
}
```

### 2.2 越权测试清单（每次发版必跑）

- [ ] 用户 A 的 token 访问用户 B 的资源 id → 404
- [ ] 租户 A 的 token 访问租户 B 的数据 → 空结果 / 404
- [ ] 无权限点调用接口 → 403（不是 200 空数据）
- [ ] 普通用户调用管理员接口 → 403
- [ ] 前端隐藏的按钮，直接调 API → 403
- [ ] 导出接口不带数据权限过滤 → 必须失败

## 3. 等保三级映射（关键条款）

| 控制项 | 要求 | 本方案落点 |
|---|---|---|
| 身份鉴别 | 唯一标识、复杂度、定期更换、双因素 | 用户表唯一约束、密码策略、MFA |
| 访问控制 | 最小权限、职责分离、默认拒绝 | RBAC + 数据权限 + 默认拒绝路由 |
| 安全审计 | 覆盖每个用户、关键操作、不可删除、留存 ≥ 6 个月 | `sys.audit_log` 分区 + 只追加 + 哈希链 |
| 入侵防范 | 最小服务、漏洞修补、防暴力破解 | 精简镜像、月度补丁、登录锁定 + 限流 |
| 恶意代码防范 | 上传文件检测 | 类型白名单 + 魔数校验 + 病毒扫描钩子 |
| 数据完整性 | 传输/存储完整性校验 | TLS、备份校验和、审计哈希链 |
| 数据保密性 | 敏感数据加密 | 字段加密、磁盘加密 |
| 数据备份恢复 | 每日备份、异地、定期演练 | pgBackRest + 季度演练 |
| 剩余信息保护 | 删除后不可恢复 | 硬删除 + 磁盘擦除策略 |
| 个人信息保护 | 最小收集、脱敏展示、授权访问 | 字段级权限 + 脱敏 + 导出审计 |

> 交付私有化项目时，把本表作为**等保测评应答材料**的基础，逐条附证据（配置截图/代码位置/测试报告）。

## 4. 可观测性

### 4.1 三支柱

| 支柱 | 内容 | 存储 |
|---|---|---|
| Metrics | 请求量/延迟/错误率、DB 池、队列积压、任务失败 | Prometheus（保留 30 天） |
| Traces | 全链路 span（HTTP → service → SQL） | OTel Collector → Tempo/Jaeger（7 天） |
| Logs | 结构化 JSON，按 trace_id 关联 | Loki/ES（30 天，审计单独 6 个月） |

### 4.2 指标清单（必须埋）

| 类别 | 指标 | 告警 |
|---|---|---|
| 流量 | `http_requests_total{route,status,method}` | — |
| 延迟 | `http_request_duration_seconds` P50/P95/P99 | P95 > 500ms 持续 5min |
| 错误 | `5xx` 率、`4xx` 率 | 5xx > 1% 持续 3min |
| 饱和度 | CPU、内存、连接池使用率、`db_pool_saturated` | > 80% 持续 10min；`db_pool_saturated=1` 持续 2min |
| 过载 | `http_requests_total{status="503"}`（并发上限/阻塞池） | > 1% 持续 3min（说明容量不足或遭遇突发） |
| DB | 慢查询数、长事务、复制延迟、连接数 | 见 03 文档 |
| 队列 | `outbox_pending`、`job_failed_total` | pending > 1000 或失败 > 10/min |
| 业务 | 登录失败率、导出任务数、审批积压 | 按业务定 |

### 4.3 SLO 与错误预算

| SLI | SLO | 错误预算（30 天） |
|---|---|---|
| 可用性（非 5xx 比例） | 99.9% | 43 分钟 |
| 延迟（P95 < 200ms） | 99% | 7.2 小时 |
| 登录成功率 | 99.5% | 3.6 小时 |

- 错误预算耗尽 → **冻结功能发布**，只允许修复类变更。
- 每月复盘 SLO 达成情况，纳入团队考核。

### 4.4 告警分级

| 级别 | 定义 | 响应 | 通道 |
|---|---|---|---|
| P0 | 全站不可用/数据泄漏 | 5 分钟 | 电话 + 群 |
| P1 | 核心功能不可用/错误率 > 5% | 15 分钟 | 电话 + 群 |
| P2 | 部分功能降级/延迟升高 | 1 小时 | 群 |
| P3 | 容量预警/非核心异常 | 次日 | 工单 |

**告警原则**：每条告警必须有 Runbook 链接；无处置动作的告警直接删掉（防告警疲劳）。

## 5. 发布与变更

### 5.1 分支模型（Trunk-Based）

```
main ──●──●──●──●──●──▶  始终可发布
        \    /
     feature/x（生命周期 < 3 天）
```

- 小步提交，PR ≤ 400 行。
- 大功能用 **Feature Flag** 隐藏，不合长命分支。
- 发布打 tag：`v1.4.2`，自动生成 CHANGELOG。

### 5.2 流水线

```
┌─ 提交阶段（< 5min）
│  fmt → clippy -D warnings → 单测 → vue-tsc → eslint
├─ 集成阶段（< 15min）
│  sqlx::test 集成测试 → openapi 快照 → 前端 build + 体积检查
├─ 安全阶段
│  cargo audit / deny / SBOM / 镜像扫描（Trivy）
├─ 预发阶段
│  部署 staging → 冒烟 E2E → 压测基线对比
└─ 生产阶段
   灰度 10% → 观察 15min → 50% → 观察 → 100%
   任一步指标劣化 → 自动回滚
```

### 5.3 数据库迁移与代码发布的顺序（关键）

```
兼容窗口内必须满足：旧代码能跑新 schema，新代码能跑旧 schema

Step 1  发布迁移（Expand：只加不减）
Step 2  发布新代码（双写/双读开关）
Step 3  数据回填（后台任务）
Step 4  切换读路径
Step 5  下个版本移除旧列（Contract）
```

**禁止**：迁移与代码同版本强耦合（回滚即灾难）。

### 5.4 回滚策略

| 场景 | 手段 | 目标时间 |
|---|---|---|
| 应用缺陷 | 回滚镜像到上一 tag | < 5min |
| 配置错误 | 配置中心回滚 + 重启 | < 3min |
| 数据错误 | 反向迁移脚本 / PITR | < 30min |
| 依赖故障 | 熔断 + 降级开关 | < 1min |

## 6. 灾备与降级

### 6.1 容灾等级

| 级别 | 方案 | RPO | RTO |
|---|---|---|---|
| L1 | 单机 + 每日备份 | 24h | 4h |
| L2 | 主备 + WAL 归档 | 5min | 30min |
| L3 | 同城双活 + 异地备份 | 秒级 | 15min |

私有化默认 L1/L2，SaaS 要求 L2 起步。

### 6.2 降级开关（必须预置）

| 依赖 | 降级行为 |
|---|---|
| Redis 不可用 | 本地缓存兜底；限流退化为单机；会话校验直连 DB |
| 对象存储不可用 | 上传返回 503 并提示；下载走本地缓存副本（若有） |
| 外部短信/邮件 | 进重试队列，界面提示"稍后发送" |
| 报表库不可用 | 报表页显示"数据服务维护中"，不影响主业务 |
| 某插件故障 | 该插件路由 503，其余正常（`optional` 机制） |

### 6.3 演练计划

| 演练 | 频率 | 验收 |
|---|---|---|
| 备份恢复 | 每季度 | 恢复到指定时间点，数据校验通过 |
| 主备切换 | 每半年 | RTO < 30min，业务无感 |
| 依赖故障注入 | 每季度 | 降级生效，无 5xx 雪崩 |
| 全链路压测 | 每大版本 | 达到 18.3 指标 |

## 7. 交付形态

### 7.1 私有化（主战场）

```
zcadmin-1.4.2-linux-amd64.tar.gz
├── zcadmin                 # 单二进制（内嵌前端）
├── config/
│   ├── default.toml
│   └── production.toml.example
├── migrations/             # 兜底（正常由程序内嵌执行）
├── docker-compose.yml
├── install.sh              # 一键安装：检查依赖、建库、初始化
├── LICENSE
├── SBOM.json
└── docs/                   # 部署手册、运维手册、等保应答
```

| 交付项 | 说明 |
|---|---|
| 许可证 | 离线 license 文件（签名 + 到期日 + 授权用户数/插件） |
| 初始化 | 首次启动生成管理员随机密码，强制修改 |
| 升级 | 停旧 → 备份 → 启新（自动迁移）→ 健康检查 → 失败自动回滚 |
| 离线安装 | 依赖全部静态链接（musl），无需目标机装 Rust/Node |

**上线前必须设置的环境变量（缺失即视为安全配置不合格）**：

| 变量 | 必填条件 | 说明 |
|---|---|---|
| `AUTH_DEV_PASSWORD` | 生产必填 | release 构建启动时会校验强度 |
| `TRUSTED_PROXIES` | 部署在网关/负载均衡后必填 | 否则审计与限流记录的是代理 IP |
| `METRICS_TOKEN` | `/metrics` 对外可达时必填 | 未设置时任何能访问该端口的人都能读到指标 |
| `EXPOSE_API_DOCS=false` | 面向公网时必填 | 关闭 `/docs` 与 `/api/openapi.json` |
| `LOG_FORMAT=json` | 接入日志平台时 | 否则是 pretty 多行格式，采集器无法按行解析 |
| `DB_MAX_CONNECTIONS` | 多实例部署时 | 单实例默认 20；**实例数 × 池上限** 不能超过 PG 的 `max_connections` 预算 |
| `STATEMENT_TIMEOUT_SECS` | 一般不用改 | 默认 5；必须小于 `request_timeout_secs`，启动期校验 |
| `BLOCKING_MAX_CONCURRENCY` | 大内存机型可调 | 默认 4；每个 Argon2 并发约 19MiB，上调前先算内存 |
| `LOGIN_RATE_LIMIT_PER_MIN` | 按需 | 默认 60；多实例时实际阈值 = 该值 × 实例数（进程内计数） |
| `OTEL_TRACES_SAMPLER_ARG` | 排障时 | 覆盖 `sample_ratio`；全量采样只在短期排障时开 |

**基础配置覆盖与启动校验（2026-11-10）**：完整变量表见
[基础功能报告 · 部署配置](./基础功能分析与加固-2026-11-10.md#部署配置)，读取实现为 `config/env.rs`，校验为 `config/loading.rs`。

- HTTP：`REQUEST_TIMEOUT_SECS`、`MAX_CONCURRENCY`、`SHUTDOWN_GRACE_SECS`；连接池：`DB_MAX_CONNECTIONS`、`DB_MIN_CONNECTIONS`、`DB_ACQUIRE_TIMEOUT_SECS`、`DB_MAX_LIFETIME_SECS`。
- 认证：`AUTH_SINGLE_SESSION`、`AUTH_SESSION_TTL_SECS`、`AUTH_MAX_FAILED_ATTEMPTS`、`AUTH_LOCK_SECONDS`；初始化账号变量仅作用于空库，不覆盖存量账号密码。
- 文件与维护：`STORAGE_LOCAL_DIR`、`STORAGE_MAX_FILE_BYTES`、`AUDIT_RETENTION_DAYS`、`TENANT_RETENTION_DAYS`、`TENANT_BILL_OVERDUE_DAYS`。
- Config 解析的数字/布尔值格式错误会中止启动，错误仅报告变量名；布尔值支持 true/false、1/0、yes/no。
- 请求超时必须分别大于获取连接和单条 SQL 超时，后两者必须大于 0；连接池预热数不能大于最大连接数。SQL 超时填 0 不再用于关闭保护。
- `BLOCKING_MAX_CONCURRENCY`、`LOGIN_RATE_LIMIT_PER_MIN`、`METRICS_TOKEN` 等由各模块读取，不应从 Config 的校验结论推断这些变量也经过相同校验。

`docker-compose.yml` 已设置 `stop_grace_period: 40s`，必须大于
`SHUTDOWN_GRACE_SECS`（默认 20）+ 3s 摘流缓冲，否则滚动发布会被 SIGKILL 打断。

### 7.2 SaaS

| 项 | 方案 |
|---|---|
| 租户开通 | 自助注册 / 后台开通，初始化租户数据 |
| 计费 | 按用户数/插件/调用量，用量采集进 `sys.usage` |
| 隔离 | 行级 RLS（默认）；大客户独立 schema |
| 限流 | 按租户令牌桶，防单租户打爆 |
| 数据导出/删除 | 租户可自助导出全部数据（GDPR/个人信息保护法） |

### 7.3 许可与合规

- 开源依赖许可证扫描（`cargo deny`），**禁止 GPL/AGPL 进入闭源交付**。
- 自研代码版权声明、第三方 NOTICE 文件。
- 出口管制：加密算法使用需符合当地法规（默认 rustls + AES-GCM）。

## 8. 运维手册要点

### 8.1 健康检查

| 端点 | 语义 | 失败行为 |
|---|---|---|
| `/healthz` | 进程存活（不查依赖） | 重启容器 |
| `/readyz` | 依赖就绪（DB/迁移完成） | 从负载均衡摘除，不重启 |
| `/metrics` | Prometheus 抓取 | 仅内网 |

### 8.2 常见故障处置

| 现象 | 排查顺序 | 处置 |
|---|---|---|
| 502/504 | 网关 → 应用日志 → DB 连接 | 扩容 / 重启 / 检查慢查询 |
| 连接池耗尽 | `db_pool_in_use` 指标 → 慢 SQL | kill 长事务 / 扩容 / 加索引 |
| 登录全部失败 | DB → 会话表 → 时钟偏移 | 校时 / 回滚配置 |
| 任务积压 | `outbox_pending` → worker 日志 | 扩容 worker / 修消费逻辑 |
| 磁盘满 | WAL 增长 → 大表 → 日志 | 清理 WAL / 归档 / 扩盘 |
| 迁移卡住 | `pg_locks` → `pg_stat_activity` | 终止阻塞会话，重试 |

基础故障语义：连接池获取超时/关闭返回 `503 + Retry-After: 5`；登录窗口限流返回
`429 + Retry-After: 60`；均为 problem+json，前端请求层不会自动重放写请求。
文件删除先提交元数据软删，提交失败保留文件；后续物理删除失败仅记录日志并保留 storage_key，
自动孤儿文件重试清理尚未实现，应在运维中核对软删记录后处理。

### 8.3 日常巡检（每日）

## 9. 安全与运维反模式

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 生产用 root/超级用户连库 | 一删全没 | 最小权限角色 |
| 日志打印完整请求体 | 密码/身份证泄漏 | 字段白名单 + 脱敏 |
| 备份只在本地 | 机房故障全丢 | 异地 + 加密 |
| 没有演练的备份 | 真恢复时失败 | 季度演练 |
| 迁移与代码同版本 | 无法回滚 | Expand-Contract |
| 告警发给所有人 | 无人处理 | 分级 + 值班 |
| 只监控 CPU | 业务故障发现不了 | RED + USE + 业务指标 |
| 关闭审计以提性能 | 合规不通过 | 异步写 + 分区 |
| 手动改生产数据 | 不可追溯 | 走脚本 + 审批 |
| 用 `latest` 镜像 | 版本不可复现 | 固定 digest |

## 登录失败锁定

- 连续失败 `max_failed_attempts`（默认 5）次后，账号锁定 `lock_seconds`（默认 900 秒）；
- 计数存在 `sys_user.failed_attempts`，多实例共享，不依赖 Redis；
- 锁定期间即使密码正确也返回 401，避免"密码是否正确"的探测；
- 登录成功自动清零；
- 锁定与失败都会写审计（`auth.login.locked` / `auth.login.failed`）。

> 管理员解锁：`UPDATE sys_user SET locked_until = NULL, failed_attempts = 0 WHERE ...`
> （注意 RLS FORCE 下需先 `set_config('app.tenant_id', ...)`）

## 安全加固（2026-11）

本轮针对审计发现的越权与默认配置问题做了以下调整，落地细节见 docs/adr/0001-平台与租户权限分域.md：

### 平台与租户权限分域

- sys_permission.scope ∈ {platform, tenant}；system:tenant:* 为平台级。
- create_tenant 创建的租户管理员 is_super = false，改为绑定 	enant_admin 角色（仅租户级权限）。
- list_permissions 按身份过滤；set_role_permissions 拒绝授予平台级权限。

### 关联表行级隔离

- sys_user_role / sys_role_permission / sys_user_post 启用并 FORCE RLS，
  策略按父表（sys_user / sys_role）可见性判断；
- set_user_roles / get_user_roles 增加租户归属校验。

### 会话即时失效

- 禁用/锁定用户、修改用户角色、修改角色权限后立即吊销相关会话；
- `revoke` / `remove` 同步清理本地缓存，强制下线不再有 30 秒窗口。

### CSRF 纵深防御

- 会话 Cookie 为 `SameSite=Lax`，跨站表单 POST 默认不带 Cookie；
- 新增 `kernel::csrf` 中间件：对 `POST/PUT/PATCH/DELETE` 校验
  `Sec-Fetch-Site`（cross-site 直接 403）与 `Origin`/`Host` 同源；
- 无 `Origin` 的非浏览器客户端（curl、服务端调用、集成测试）放行，由认证与权限点负责；
- 提供 6 个单元测试覆盖同源/跨源/缺省头等分支。

### 默认安全

- 所有响应注入 CSP、X-Frame-Options、X-Content-Type-Options、Referrer-Policy、Permissions-Policy，release 加 HSTS；
- CSP 的 `connect-src` 收敛为 `'self'`（不再放行 `ws:` / `wss:`），并加 `object-src 'none'`；
  将来接入 WebSocket 网关时，必须显式加回**具体域名**，不要用通配；
- /metrics 支持 METRICS_TOKEN（Bearer）保护，未设置时保持开放以兼容内网抓取；
  token 比较使用常量时间实现；
- `/docs` 与 `/api/openapi.json` 可用 `EXPOSE_API_DOCS=false` 关闭（公网部署必须关闭）；
- 全局请求体上限 2MB（`DefaultBodyLimit`），仅上传（25MB）与用户导入（10MB）单独放宽；
- docker-compose 的应用连接改为 zcadmin_app（NOSUPERUSER NOBYPASSRLS），
  超级用户仅用于初始化（ops/init-app-role.sql）。

### 客户端 IP 与限流（2026-11 加固）

改前：`X-Forwarded-For` 第一段无条件采信 → 攻击者换一个伪造头就能绕过按 IP 的登录限流，
审计里的 IP 也不可信。

改后（详见 ADR-0006）：

- 一律以 **TCP 对端地址**为准；只有对端落在 `trusted_proxies`（CIDR 白名单）内才解析 XFF；
- XFF 从**右往左**取第一个不可信地址（左侧可被终端用户伪造）；
- 解析结果写入请求扩展（`ClientMeta`），限流/审计/日志统一消费，禁止各自读请求头；
- 生产入口必须用 `into_make_service_with_connect_info::<SocketAddr>()`，否则整条链路失效；
- 未配置 `TRUSTED_PROXIES` 时，审计记录的是代理地址——这是**配置缺失**而不是 bug，
  已列入 §7.1「上线前必须设置的环境变量」。

### 账号枚举的时序防护（2026-11 加固）

改前：用户不存在/已停用/已锁定 时立即返回 401，而真实用户要等 40~60ms 的 Argon2，
响应时间本身就能用来枚举账号。

改后：上述三个分支都执行一次与真实校验等价的 Argon2 计算
（`password::burn_verification_time`），让两条路径耗时对齐。

### 数据正确性

- 客户 Excel 导出补「状态」列，表头与数据列严格一致；
- 回款软删/恢复会正确冲减 contract.paid_cents 与 payment_daily（迁移 0017 含历史回填）；
- 账单重复生成只更新 draft，不会覆盖已出账/已收款账单；
- 导入逐行 SAVEPOINT，单行冲突不再中止整批。
