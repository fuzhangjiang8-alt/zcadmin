# 04 · 插件体系

> 目标：**内核一年不动，业务插件每天在长**｜形态：crate 级编译期插件（默认）+ WASM / 独立服务（可选）

---

## 1. 为什么不是动态库

| 方案 | 可行性 | 结论 |
|---|---|---|
| `libloading` + C ABI | 手写 `extern "C"`，无法传 axum Router/sqlx 类型 | ❌ |
| `abi_stable` | 需所有跨边界类型实现 `StableAbi`，版本漂移即 UB | ❌ |
| WASM 组件 | 沙箱安全，但无法直接访问 PG，只能走宿主 API | ⚠️ 仅限扩展点 |
| 独立进程 | 真隔离、可真热更 | ⚠️ 运维成本高 |
| **编译期 crate** | 类型安全、零开销、可内联优化 | ✅ 默认 |

**核心判断**：企业后台的插件需求本质是「**代码组织与发布解耦**」，不是「运行时热插拔」。前者用 crate 完美解决，后者用 WASM/独立进程按需补充。

---

## 2. 三种形态与决策树

```
需要热更新？
├─ 否 → 自有团队？ → 是 → 【A. 编译期 crate】（默认）
│                    └ 否 → 第三方不可信？ → 是 → 【B. WASM 组件】
└─ 是 → 需要独立扩缩容/异构语言？ → 是 → 【C. 独立服务】
                                  └ 否 → 【B. WASM 组件】
```

| 维度 | A. 编译期 crate | B. WASM | C. 独立服务 |
|---|---|---|---|
| 性能 | 进程内调用，零开销 | 有序列化开销（~μs） | 网络跳转（~ms） |
| 隔离 | 无（同进程） | 沙箱（内存/系统调用） | 进程级 |
| 热更新 | 需重新发布 | 支持 | 支持 |
| 能否直连 PG | 能 | 不能（走宿主 API） | 能（自己的连接） |
| 开发体验 | 最好（IDE 全功能） | 一般（需 wit-bindgen） | 好 |
| 适用 | 业务模块 90% | 规则钩子、脚本、三方扩展 | 遗留系统、异构、独立扩容 |

## 3. 契约定义（完整版）

```rust
// crates/kernel/src/plugin.rs
use axum::Router;
use std::{future::Future, pin::Pin, sync::Arc};

pub type BoxFuture<T> = Pin<Box<dyn Future<Output = T> + Send + 'static>>;

#[derive(Clone, Copy, Debug)]
pub struct PluginMeta {
    pub id: &'static str,               // "crm"：路由前缀 / schema / 权限前缀
    pub name: &'static str,             // "客户管理"
    pub version: &'static str,          // build.rs 注入 CARGO_PKG_VERSION
    pub kernel_min: &'static str,       // 最低内核版本，如 "1.2.0"
    pub depends_on: &'static [&'static str],
    pub order: i32,                     // 同层装配顺序（小在前）
    pub optional: bool,                 // 启动失败是否允许降级
    pub description: &'static str,
}

pub struct PluginCtx {
    pub db: sqlx::PgPool,
    pub events: EventBus,
    pub jobs: JobRunner,
    pub storage: Arc<dyn ObjectStore>,
    pub cfg: Arc<Config>,
    pub metrics: MetricsRegistry,
}

/// 插件生命周期钩子
pub trait Plugin: Send + Sync + 'static {
    fn meta(&self) -> PluginMeta;

    // ---- 装配期 ----
    fn migrations(&self) -> &'static [Migration] { &[] }
    fn permissions(&self) -> Vec<PermissionDef> { Vec::new() }
    fn menus(&self) -> Vec<MenuDef> { Vec::new() }
    fn dicts(&self) -> Vec<DictDef> { Vec::new() }
    fn jobs(&self) -> Vec<JobDef> { Vec::new() }
    fn config_schema(&self) -> Option<ConfigSchema> { None }   // 插件级配置项（前端可渲染）

    // ---- 运行期 ----
    fn routes(&self) -> Router<AppState> { Router::new() }
    fn subscribers(&self) -> Vec<Box<dyn EventSubscriber>> { Vec::new() }

    // ---- 生命周期 ----
    fn on_register(&self, _ctx: &PluginCtx) -> BoxFuture<anyhow::Result<()>> { Box::pin(async { Ok(()) }) }
    fn on_start<'a>(&'a self, _ctx: &'a PluginCtx) -> BoxFuture<anyhow::Result<()>> { Box::pin(async { Ok(()) }) }
    fn on_stop<'a>(&'a self, _ctx: &'a PluginCtx) -> BoxFuture<()> { Box::pin(async {}) }

    // ---- 健康检查 ----
    fn health(&self) -> HealthStatus { HealthStatus::Healthy }
}

inventory::collect!(&'static dyn Plugin);
```

### 3.1 声明宏（降低样板）

```rust
// plugins/crm/src/lib.rs
pub struct CrmPlugin;

impl Plugin for CrmPlugin {
    fn meta(&self) -> PluginMeta {
        PluginMeta {
            id: "crm", name: "客户管理", version: env!("CARGO_PKG_VERSION"),
            kernel_min: "1.2.0", depends_on: &["system"], order: 100,
            optional: false, description: "客户/联系人/商机管理",
        }
    }

    fn routes(&self) -> Router<AppState> {
        Router::new()
            .route("/customers", get(api::customer::list).post(api::customer::create))
            .route("/customers/{id}", get(api::customer::get)
                                        .patch(api::customer::update)
                                        .delete(api::customer::delete))
            .route("/customers/export", post(api::customer::export))
    }

    fn permissions(&self) -> Vec<PermissionDef> {
        perms![
            "customer:list"   => "客户查询",
            "customer:get"    => "客户详情",
            "customer:add"    => "客户新增",
            "customer:edit"   => "客户编辑",
            "customer:delete" => "客户删除",
            "customer:export" => "客户导出",
        ]
    }

    fn menus(&self) -> Vec<MenuDef> {
        menu! {
            "客户管理" => "/crm", icon: "user",
            children: [
                { "客户列表" => "/crm/customer", component: "crm/customer/index", perm: "crm:customer:list" },
            ]
        }
    }
}

inventory::submit! { &CrmPlugin as &'static dyn Plugin }
```

> `perms!` 自动补全 `{plugin_id}:` 前缀，避免手写不一致。

## 4. 生命周期状态机

```
              ┌──────────────┐
              │  Discovered  │  inventory 收集到
              └──────┬───────┘
                     │ 校验 kernel_min / 依赖存在 / 无环
              ┌──────▼───────┐
              │  Validated   │  失败 → 启动中止（或 optional 跳过）
              └──────┬───────┘
                     │ 建 schema（CREATE SCHEMA IF NOT EXISTS）
              ┌──────▼───────┐
              │  Migrated    │  执行 migrations，失败即整体回滚
              └──────┬───────┘
                     │ upsert 权限点/菜单/字典/任务
              ┌──────▼───────┐
              │   Seeded     │
              └──────┬───────┘
                     │ on_register（注册事件订阅、任务 handler）
              ┌──────▼───────┐
              │  Registered  │
              └──────┬───────┘
                     │ on_start（预热缓存、建外部连接）
              ┌──────▼───────┐
              │   Running    │◀──── health() 周期检查
              └──────┬───────┘
                     │ 进程退出（逆序）
              ┌──────▼───────┐
              │   Stopped    │  on_stop：释放资源、停订阅
              └──────────────┘
```

| 阶段 | 失败策略 |
|---|---|
| Validated | 整体启动失败（依赖缺失是配置错误，不能带病运行） |
| Migrated | 整体启动失败；迁移在事务内，失败自动回滚 |
| Seeded | 整体启动失败（种子缺失会导致权限错乱） |
| on_start | `optional = true` → 该插件路由返回 503，其余正常；否则整体失败 |
| Running 期 panic | `CatchPanicLayer` 捕获 → 该请求 500，进程存活（ADR-0004）；**"连续 10 次/分钟熔断"尚未实现** |

> 现状：`Plugin` trait **没有** `on_start` 方法，启动流程也没有调用它；`optional` 标志同样未落地。
> 上表中 `on_start` 那一行是目标语义，不是当前行为。落地进度以 `crates/kernel/src/app.rs` 为准。

## 5. 依赖与版本

### 5.1 版本规则（SemVer）

| 变更 | 版本 | 影响 |
|---|---|---|
| 新增接口/字段 | MINOR | 向后兼容 |
| 修复 | PATCH | — |
| 删除/改语义/改权限点 | **MAJOR** | 需迁移方案 + 公告 |

```toml
# plugins/crm/Cargo.toml
[package]
name = "plugin-crm"
version = "1.4.2"

[dependencies]
kernel = { path = "../../crates/kernel", version = "1.2" }
```

### 5.2 兼容矩阵

| 内核版本 | crm | wms | oa |
|---|---|---|---|
| 1.2.x | 1.3–1.4 | 2.0–2.1 | 1.0 |
| 1.3.x | 1.4–1.5 | 2.1–2.2 | 1.0–1.1 |

- 插件声明 `kernel_min`，内核启动时校验。
- CI 维护**兼容矩阵**：内核每次发版，跑一遍所有插件的编译 + 集成测试。

### 5.3 依赖解析

```rust
// 拓扑排序 + 环检测
fn resolve(plugins: &[&'static dyn Plugin]) -> Result<Vec<&'static dyn Plugin>> {
    let mut sorted = Vec::new();
    let mut visiting = HashSet::new();
    let mut visited = HashSet::new();

    fn visit<'a>(p: &'a &'static dyn Plugin, ...) -> Result<()> {
        if visiting.contains(&p.meta().id) { bail!("插件依赖成环: {}", p.meta().id); }
        if visited.contains(&p.meta().id) { return Ok(()); }
        visiting.insert(p.meta().id);
        for dep in p.meta().depends_on {
            let d = by_id(dep).ok_or_else(|| anyhow!("缺少依赖插件 {dep}"))?;
            visit(d, ...)?;
        }
        visiting.remove(&p.meta().id);
        visited.insert(p.meta().id);
        sorted.push(*p);
        Ok(())
    }
    // ...
}
```

**规则**：
- 依赖必须显式声明，禁止"隐式依赖"（如假设 `system` 已建表）。
- 禁止环形依赖；发现即架构评审。
- 依赖层级建议 ≤ 3 层（system → domain → feature）。

## 6. 装配器（AppBuilder）

```rust
pub struct AppBuilder {
    cfg: Config,
    pool: PgPool,
    plugins: Vec<&'static dyn Plugin>,
}

impl AppBuilder {
    pub async fn build(cfg: Config) -> anyhow::Result<axum::Router> {
        let pool = db::connect(&cfg).await?;

        // 1. 收集 + 拓扑排序
        let all: Vec<_> = inventory::iter::<&'static dyn Plugin>.into_iter().copied().collect();
        let plugins = resolve(&all)?;

        // 2. 迁移串行执行，全局锁防多实例并发迁移
        let _lock = db::advisory_lock(&pool, "sys.migrate").await?;
        for p in &plugins {
            db::ensure_schema(&pool, p.meta().id).await?;
            p.migrate(&pool).await?;            // SET search_path 后执行
            p.seed(&pool).await?;               // 权限点/菜单/字典/任务 upsert
        }

        // 3. 并行调用 on_register（无副作用顺序要求）
        for p in &plugins { p.on_register(&ctx).await?; }

        // 4. 挂载路由
        let mut app = Router::new();
        for p in &plugins {
            app = app.nest(&format!("/api/{}", p.meta().id), p.routes());
        }

        // 5. on_start 并行，单个超时 10s
        for p in &plugins { timeout(10s, p.on_start(&ctx)).await??; }

        Ok(app.with_state(state).layer(middleware_stack()))
    }
}
```

**迁移锁**：多实例同时启动时，只有一个执行迁移，其余等待（`pg_advisory_lock`），避免并发 DDL 冲突。

> **必须显式链接插件 crate**：链接器会丢弃「没有任何符号被引用」的 crate，连同 `inventory::submit!` 的注册代码一起消失 —— 表现为「依赖加了、插件却没挂载」。
> 解决办法是在 `apps/server/src/main.rs` 顶部写：
> ```rust
> use plugin_crm as _;
> use plugin_demo as _;
> ```
> 这一行没有实际调用，作用是强制链接。`cargo xtask new-plugin` 生成插件后必须同步补上。

## 7. 数据隔离

| 边界 | 规则 |
|---|---|
| Schema | 插件只能写 `plg_{id}`；读 `sys` 允许；读写其他插件 schema **禁止**（DB 权限层拒绝） |
| 跨插件读 | 对方提供 `v_public_*` 视图（只读、脱敏、稳定契约），`GRANT SELECT` 给 `app_rw` |
| 跨插件写 | **禁止**；只能发事件，由对方订阅处理 |
| 外键 | 禁止跨 schema 外键（用逻辑引用 + 对账任务） |
| 事务 | 一个事务只能写一个插件的表（跨插件事务破坏解耦） |
| 迁移 | 每个插件独立 `migrations/`，不可修改已发布迁移 |
| 卸载 | `DROP SCHEMA plg_x CASCADE` + 删除权限点/菜单/任务定义 |

### 7.1 插件里的重 CPU 操作

插件同样跑在内核的 tokio runtime 上，**没有独立的线程/内存隔离**，因此：

- 密码哈希、Excel/Word 解析生成、图片处理、同步文件 IO 必须走
  `kernel::blocking::run`（受控阻塞池，默认并发 4，排队超时返回 503）；
- **禁止**直接 `tokio::task::spawn_blocking`：它没有并发上限，
  在 Argon2 这类内存硬算法上会直接把进程 OOM（见 ADR-0005）；
- 禁止在 handler 里 `std::thread::sleep` / `block_on` / 同步 `std::fs`。
- 插件声明的后台任务必须是幂等的（当前无 `JobRunner`，用 `tokio::spawn` + `interval`），
  多实例会各跑一份。

```sql
-- 插件对外暴露的只读视图（契约）
CREATE VIEW plg_crm.v_public_customer AS
SELECT id, tenant_id, code, name, level, status
FROM plg_crm.customer WHERE deleted_at IS NULL;
GRANT SELECT ON plg_crm.v_public_customer TO app_rw;
```

## 8. 前端插件契约

```ts
// packages/sdk/src/plugin.ts
export interface AdminPlugin {
  id: string;                        // 与后端插件 id 一致
  name: string;
  version: string;
  kernelRange: string;               // ">=1.2.0 <2.0.0"
  routes: PluginRoute[];
  locales?: Record<string, Record<string, string>>;
  setup?: (ctx: PluginSetupCtx) => void;   // 注册全局组件/指令
}

export interface PluginRoute {
  name: string;                      // 全局唯一，建议 "{plugin}-{page}"
  path: string;                      // 必须以 /{id} 开头
  component: () => Promise<any>;
  meta: { title: string; icon?: string; perm?: string; keepAlive?: boolean; hidden?: boolean };
}
```

```ts
// plugins-web/crm-web/plugin.ts
import { definePlugin } from '@admin/sdk';

export default definePlugin({
  id: 'crm',
  name: '客户管理',
  version: '1.4.2',
  kernelRange: '>=1.2.0 <2.0.0',
  routes: [
    { name: 'crm-customer', path: '/crm/customer',
      component: () => import('./views/CustomerList.vue'),
      meta: { title: '客户列表', perm: 'crm:customer:list', keepAlive: true } },
    { name: 'crm-customer-detail', path: '/crm/customer/:id',
      component: () => import('./views/CustomerDetail.vue'),
      meta: { title: '客户详情', perm: 'crm:customer:get', hidden: true } },
  ],
  locales: { 'zh-CN': { 'crm.customer.name': '客户名称' } },
});
```

| 约束 | 说明 |
|---|---|
| 路由前缀 | 必须 `/{pluginId}`，装配时校验，冲突直接构建失败 |
| 路由名 | 全局唯一，建议 `{plugin}-{page}`，避免 keep-alive 失效 |
| 样式 | 所有样式 scoped 或加 `[data-plugin]` 前缀，禁止全局选择器 |
| 依赖 | 只能 `@admin/sdk`、`@admin/ui`、`@admin/utils` |
| i18n | key 必须带插件命名空间前缀 |
| 权限点 | 必须与后端 `permissions()` 完全一致（CI 校验） |

**权限点一致性校验**（`xtask check-perms`）：

```
读取后端 openapi / permissions 清单 ↔ 读取前端 plugin.ts 的 meta.perm
差异 → CI 失败
```

## 10. 注册表与分发

| 方式 | 适用 | 说明 |
|---|---|---|
| 同仓 workspace | 自有团队（默认） | 最简单，统一 CI |
| Git 依赖 | 跨仓协作 | `plugin-crm = { git = "ssh://...", tag = "v1.4.2" }` |
| 私有 registry | 三方/多团队 | `cargo` 私有源（Kellnr / Artifactory） |
| 离线包 | 私有化交付 | 源码 tar + `vendor/` 目录，`cargo build --offline` |

```toml
# apps/server/Cargo.toml —— 唯一的"插件清单"
[dependencies]
plugin-system = { path = "../../plugins/system" }
plugin-crm    = { path = "../../plugins/crm", optional = true }
plugin-wms    = { path = "../../plugins/wms", optional = true }

[features]
default = ["crm"]
crm = ["dep:plugin-crm"]
wms = ["dep:plugin-wms"]
```

```bash
# 客户 A 只要 CRM
cargo build --release --no-default-features --features crm
```

> **按客户裁剪**：feature 组合 + 配置文件，同一个代码库交付不同功能集，二进制更小、攻击面更少。

## 11. 多版本与灰度

| 维度 | 机制 |
|---|---|
| 插件版本 | 编译期固定（一个二进制一套版本） |
| 租户级开关 | `sys_tenant_feature(tenant_id, feature, enabled)`，路由层拦截 |
| 灰度发布 | 按租户/用户比例路由到新版本实例（网关权重） |
| A/B | 新旧逻辑并存，配置切换，观察指标后下线旧逻辑 |
| 降级 | `optional` 插件失败 → 菜单置灰 + 接口 503 + 告警 |

```rust
// 功能开关中间件
if !features.enabled(ctx.tenant.id, "crm.v2") {
    return Err(AppError::NotFound);   // 未开通 → 404，不暴露功能存在
}
```

## 12. 治理

| 事项 | 规则 |
|---|---|
| CODEOWNERS | 每个 `plugins/*` 目录指定 owner，PR 必须 owner 批准 |
| 内核变更 | 需架构评审 + 影响所有插件的兼容性评估 |
| 契约变更 | `Plugin` trait 变更视为 MAJOR，需提供默认实现以保证兼容 |
| 插件 SLA | 核心插件 99.9%，非核心 99.5%，写进值班手册 |
| 退役 | 公告 2 个版本 → 停止新租户开通 → 数据归档 → 删除代码与 schema |
| 文档 | 每个插件必须有 README：功能、权限点、表结构、事件、负责人 |
| 度量 | 每插件统计：代码行数、接口数、表数、错误率、P95 |

## 13. 反模式

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 插件直接 `use` 另一个插件 | 无法独立发布，循环依赖 | 事件 / contract crate |
| 插件写 `sys` 表 | 内核数据被污染 | 调 kernel 提供的 API |
| 插件跨 schema 建外键 | 卸载/迁移受阻 | 逻辑引用 + 对账 |
| 迁移文件发布后修改 | 各环境 schema 漂移 | 只能新增 |
| 插件注册根路由 `/api/*` | 与其他插件冲突 | 固定 `/{id}` 前缀 |
| 在插件里 `std::process::exit` | 一个插件拖垮全进程 | 返回错误，交给框架 |
| 插件里起无限后台线程 | 无法优雅停机、线程泄漏 | 用 `JobRunner` |
| 前端插件全局样式 | 污染宿主与其他插件 | scoped + 前缀 |
| 一个插件包揽多个业务域 | 变成"第二个单体" | 按限界上下文拆分 |
| 权限点手写字符串 | 前后端不一致 | 宏生成 + CI 校验 |


## 插件导入（ImportRegistration）

与导出一致，插件用 `inventory::submit!` 注册：

```rust
inventory::submit! {
    kernel::imports::ImportRegistration {
        kind: "crm.contracts",
        permission: "crm:contract:add",
        run: contracts,
    }
}
```

内核提供 `POST /api/system/imports/{kind}`：

- 校验登录与权限（取自注册项）；
- 读取 multipart 的 `file` 字段；
- 在请求级事务中调用插件解析函数；
- 统一返回 `{ success, failed, errors[] }`。

插件只负责 xlsx 解析与写库，不关心上传、鉴权、事务。
