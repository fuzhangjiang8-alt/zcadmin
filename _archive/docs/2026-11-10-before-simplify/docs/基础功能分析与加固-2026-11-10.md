## 已修复问题

| 能力 | 原有问题 | 完善后的行为与主要位置 |
|---|---|---|
| 配置覆盖 | 非法数字被忽略，部分部署参数不能通过环境变量覆盖 | `config/env.rs` 显式解析，错误只显示变量名；超时/连接池/认证/存储与保留策略可覆盖 |
| 配置默认值 | 缺少整个 observability 段时采样率为 0，与字段缺省 0.1 不一致 | `config/loading.rs` 统一默认采样率，并校验非零 SQL 超时、超时递减与容量边界 |
| HTTP 请求 | 自定义请求头覆盖合并结果；代理 HTML/纯文本错误变成 JSON 解析异常 | `frontend/src/api/client.ts` 支持三种 HeadersInit，保留 HTTP 状态；FormData 不强制设置 Content-Type |
| 前端身份 | 退出后在途 `/me` 可恢复旧账号，旧请求 finally 可覆盖新请求状态 | `stores/session.ts` 使用代次和 Promise 身份校验，旧身份请求返回 401 |
| 前端数据 | 退出只清当前用户，字典和查询缓存可被下一账号复用 | 共享 `api/query-client.ts`；退出/重新登录清除查询；字典迁入 vue-query 并传递取消信号 |
| 单端登录 | 删除与插入分离，并发登录可能留下多会话，插入失败丢失旧会话 | `session/create.rs` 在同一事务中按租户/用户加咨询锁后替换，失败整体回滚 |
| 会话缓存 | 注销前的查询可在清缓存后回填旧权限；过期项不主动回收可能持续增长 | `session/cache.rs` 以代次保护回填，容量最多 10000 项，维持 30 秒 TTL |
| 退出登录 | 数据库撤销失败仍返回 204，前端也强制显示已退出 | 存储失败返回错误；成功才过期 Cookie、清理本地身份并跳转登录 |
| 错误响应 | AppError 使用普通 JSON 媒体类型；登录 429 为纯文本；连接池错误为 500 | 统一 problem+json；登录保留 Retry-After=60；连接池关闭/获取超时返回 503+Retry-After=5 |
| 分页 | u64 大页码乘法溢出或转为负 i64 OFFSET | `response.rs` 饱和计算，页大小仍限制 1..200 |
| 文件删除 | 提交前删除物理内容，提交失败时仍可见的元数据指向丢失内容 | `files_read.rs` 先提交软删再删文件；下载先释放只读事务再读取磁盘 |
| 用户导入 | 单行 SQL 错误使整个事务处于失败状态，影响其他行或导致统计与落库不一致 | 每行 SAVEPOINT，错误行回滚、成功行统一提交；单行写入的数据库异常细节只进入日志 |
| Excel 与初始化 | 两个基础导入导出入口同步生成 xlsx；初始化同步计算 Argon2 | `user_import_xlsx.rs` 通过既有 xlsx 阻塞池执行；错误报告最多 500 行且不含密码；初始化使用异步哈希入口 |
| 工程门禁 | 本地 verify 未包含 CI 已有的权限与错误码检查 | `cargo xtask verify` 增加第六步；新增基础真库测试放在 kernel 下，独立于插件编译 |

## 部署配置

下表由 Config 解析的环境变量，格式非法时不再降级到默认值，部署前应检查现有配置。布尔值支持 true/false、1/0、yes/no，
忽略大小写与两侧空白。列表用逗号分隔，空项忽略；空 OTLP 端点表示关闭远程追踪。

| 配置范围 | 环境变量 |
|---|---|
| HTTP | `BIND_ADDR`、`WEB_DIST`、`CORS_ORIGINS`、`TRUSTED_PROXIES`、`MAX_CONCURRENCY`、`REQUEST_TIMEOUT_SECS`、`SHUTDOWN_GRACE_SECS`、`EXPOSE_API_DOCS` |
| 数据库 | `DATABASE_URL`、`DB_MAX_CONNECTIONS`、`DB_MIN_CONNECTIONS`、`DB_ACQUIRE_TIMEOUT_SECS`、`DB_MAX_LIFETIME_SECS`、`STATEMENT_TIMEOUT_SECS` |
| 身份 | `AUTH_DEV_USERNAME`、`AUTH_DEV_PASSWORD`、`AUTH_SESSION_TTL_SECS`、`AUTH_MAX_FAILED_ATTEMPTS`、`AUTH_LOCK_SECONDS`、`AUTH_SINGLE_SESSION` |
| 文件与维护 | `STORAGE_LOCAL_DIR`、`STORAGE_MAX_FILE_BYTES`、`AUDIT_RETENTION_DAYS`、`TENANT_RETENTION_DAYS`、`TENANT_BILL_OVERDUE_DAYS` |
| 追踪 | `OTEL_EXPORTER_OTLP_ENDPOINT`、`OTEL_TRACES_SAMPLER_ARG` |

请求超时必须分别大于获取连接超时和单条语句超时，后两者不能为零；连接池预热数不能大于最大连接数。
这些约束用于已有配置项，不新增表结构或配置框架。初始化账号字段只对空库生效，不覆盖已有账号密码。

## 验证与复现

Windows GNU Rust 需要将已安装的 MinGW bin 加入当前进程 PATH。测试连接本机 PostgreSQL 时，
本轮使用 127.0.0.1；本机 localhost 的连接曾持续等待，未修改系统网络或数据库服务。

```powershell
# 基础层编译、静态检查与普通回归，不依赖插件
cargo fmt -p kernel -p xtask -- --check
cargo clippy -p kernel -p xtask --all-targets -- -D warnings
cargo test -p kernel --lib --test http_contract

# 设置测试 DATABASE_URL 后运行；sqlx::test 自动创建/删除独立测试库，需要 CREATEDB 权限
cargo test -p kernel --test session_atomicity --test file_atomicity --test user_import_atomicity -- --ignored --test-threads=1

# 全仓库门禁；默认忽略真库测试，不能替代上一条或 RLS owner 路径验证
cargo xtask verify
cargo xtask openapi

cd frontend
npm test
npm run build
npm run gen:api
```

## 剩余边界与后续工作

1. 会话缓存和登录限流仍为进程内实现。其他实例撤销会话存在最长 30 秒窗口，全局限流阈值按实例数放大。
2. 文件下载仍全量读入内存。物理删除失败只留日志与软删记录，自动孤儿文件重试清理未在本轮实现。
3. 用户导入仍同步请求、最多 500 行；Argon2 和 Excel 走受控池不等于长任务调度、进度查询或大批量导入能力。
4. 多处基础管理接口仍在 handler/read 模块中直接写 SQL，与 Repository 分层目标有差距；本轮没有做全量分层重构。
5. 导出仍有生成文件与落盘期间持有事务的路径；统一调度、事务拆分、outbox、双令牌、MFA 等需独立规格与架构评审。
6. 前端构建与 Node 回归不代表浏览器实点、视觉验收或生产部署通过。独立真库回归不代表生产连接角色下的 FORCE RLS owner/普通角色隔离已验证。

回滚方式：回退本轮基础实现及对应文档/生成契约即可；没有新增或修改迁移，不需要执行数据库回滚。
部署恢复旧版本前须确认旧版与本次环境变量覆盖配置的差异。已删除的文件仍按现有业务删除语义处理，代码回滚不恢复文件。
