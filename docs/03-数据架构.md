# 03 · 数据架构

PostgreSQL 16+是主存储。本文保留数据与迁移约束；真实表/字段以schema和迁移为准，不把旧设计DDL当生产结构。

## 1. 数据域划分

`sys`属于内核，业务插件使用自己的id作为schema（如crm/demo）。不在public随意建业务表。
跨插件不得直接use或跨表写；新跨域关系走既定事件/契约，不新增跨插件外键。rpt/stage、只读副本等需独立落地，不能假定已有。

## 2. 建模规范

| 项 | 要求 |
|---|---|
| 标识/命名 | snake_case，主键UUIDv7；沿用现有sys_*和业务表命名 |
| 业务表必备 | tenant_id、created_at、created_by、deleted_at、version，按现有约定补updated_* |
| 时间 | timestamptz，明确展示时区；禁止用无时区时间表达绝对时刻 |
| 金额 | 明确币种、单位与舍入；用numeric或既有整数分，不用浮点做金额真相源 |
| 状态 | 沿用现有枚举/CHECK；变更同时覆盖历史数据和上下游 |
| JSON | 只存扩展或快照，不能用JSON代替可约束、需关联的核心字段 |

业务唯一键必须考虑tenant及软删。父子软删、恢复冲突、历史唯一值重用要有明确规则；不要误加无法跨分区维护的唯一约束。
冗余字段只为明确查询收益，须说明更新/对账来源，不能引入无事务的缓存与DB双写。

## 3. 角色与权限模型

迁移/运维与应用角色分离；应用用NOSUPERUSER、NOBYPASSRLS。表owner仍须受FORCE RLS限制，超级用户不适合作隔离验证。
生产角色初始化见 `ops/init-app-role.sql`，核对schema权限、默认授权与后续新表/分区授权。
平台全局表、认证会话和分区子表的特殊访问路径必须单独说明，不能机械套用或跳过隔离。

## 4. 索引工程

按WHERE/JOIN/ORDER BY真实查询设计索引，租户业务查询优先tenant_id前缀；软删列表适合部分索引。
联合索引顺序根据选择性、等值/范围和排序确定，避免给每列建索引。新增复杂查询给出真实数据的EXPLAIN ANALYZE/BUFFERS及基数说明。
定期检查慢查询、无用索引、重复索引、膨胀与VACUUM；文档只保留结论和入口，完整计划放验收材料。

## 5. 分区与大表

审计按月分区，维护见audit_maintenance.rs，缺分区时不能丢日志。父表RLS、直接子表访问权限、兜底分区和未来分区需一起验证。
按增长、保留期和锁风险决定分区/归档，禁止只因行数大就换数据库。删除旧分区前核对归档和恢复策略。

## 6. 事务与并发（DBA视角）

事务边界见01§5。租户上下文必须事务级，commit/rollback后不残留。锁顺序一致，死锁/序列化失败按有界策略处理。
业务唯一约束防并发重复；版本条件防覆盖；批处理使用保存点时明确部分成功语义，不能吞异常后继续使用已失败事务。

## 7. 连接管理

默认池上限20、预热5、获取连接5秒、最大寿命1800秒，具体以配置为准。
总预算 = 实例数×各池上限 + 后台/运维/迁移连接，预留PG系统连接；根据等待、SQL耗时与负载调整，不盲目扩池。
每连接下发statement_timeout和事务空闲超时；迁移暂时放开SQL超时，使用schema咨询锁并恢复会话配置。
引入事务模式连接代理前，核对prepared statement缓存、会话配置与迁移连接兼容性。

## 8. 查询规范

所有查询经过Repository目标层并默认带权限；既有handler SQL逐步收敛，不扩大无权限查询。
值使用绑定参数，动态标识符/排序走内部白名单。列表必须分页，避免SELECT *、N+1、无界IN及同步全表聚合。
排序必须稳定并有并列键；导出按上限/游标分批，复杂报表明确主库影响与时效要求。

## 9. 多租户与RLS

### 9.1 策略与FORCE

新tenant表必须同时建立策略、ENABLE和FORCE。策略从事务级app.tenant_id取上下文，缺上下文默认不可见；写入同时限制归属。

```sql
-- 原则示例，表名与类型以本仓库真实迁移为准
ALTER TABLE schema_name.table_name ENABLE ROW LEVEL SECURITY;
ALTER TABLE schema_name.table_name FORCE ROW LEVEL SECURITY;
```

上面两句不代替CREATE POLICY；策略和FORCE必须一起交付。应用侧tenant条件与数据库RLS是双重边界，不能删除任一层。

### 9.2 生命周期

开通初始化租户管理员与基础配置；停用/软删保留数据并撤销会话；恢复需处理状态/唯一性；物理清理须过保留期且明确不可恢复。
动态清表按外键从叶到根，始终携带目标租户上下文。文件内容、关联记录和插件数据不能遗漏。

### 9.3 验证与例外

静态检查只证明迁移里策略与FORCE配套，不能证明实际部署已迁移或隔离有效。
真实测试覆盖表owner和普通角色两条路径、读写、无上下文、跨租户、分区直接访问及平台身份，命令见07。
sys_session解析token时尚不知tenant，管理操作需显式tenant过滤；sys_tenant/sys_permission是全局域。例外按源码核查，不固定抄写表数。

## 10. 数据权限与脱敏

RLS解决租户隔离，scope::condition解决部门/本人/custom可见性；功能权限是第三层。三者不可互相替代。
邮箱/手机号等按权限脱敏，导出与详情保持一致。敏感值不能写入日志、错误或无授权快照。

## 11. 审计与合规

应用记录操作者、动作、资源、结果和必要before/after，不记录口令/token。关键变更审计只描述已提交事实。
默认保留180天；具体政策、权限、分区清理和运维见05。WORM、哈希链、冷归档是目标，未经实现/验证不得宣称已具备。

## 12. 报表与分析

复杂聚合需控制行数/时间、解释计划和并发；必要时预聚合或只读副本，但必须说明复制延迟及写后读策略。
物化视图、rpt宽表或外部分析库需明确同步/回填/失败恢复，不默认为当前基础设施。

## 13. 备份与恢复

生产需全量+增量/WAL、异地加密、保留策略与密钥分离。小库可用逻辑备份，不能代替生产PITR方案。
季度在隔离实例恢复并记录实际RPO/RTO；备份成功不等于可恢复。操作步骤见05，既定目标见总览。

## 14. 高可用与扩展

优先治理索引、连接和容量，再评估主备/副本、分区/归档与大租户独立库。故障转移需验证连接重建、复制延迟和数据一致性。
分片、时序或分析库按06触发条件评审，不预先搭建。

## 15. 变更管理（DDL安全）

只能新增迁移，禁止修改已发布文件。Expand → 兼容读写 → 回填 → 验证 → Contract；旧版本仍读写时不能删字段或改含义。
评审锁级别、扫描/重写成本、索引构建方式和超时；并发建索引与事务限制按实际PG行为处理。
必须写回滚/恢复方案、校验SQL、发布顺序；不可逆变更不能以回退二进制当作完整回滚。
生成结构先改schema并正式生成；涉及SQL元数据按仓库流程执行prepare，禁止手改.sqlx。

## 16. 数据质量与监控

巡检孤儿关系、软删一致性、状态/金额约束、租户归属、分区增长、连接等待、锁与复制延迟。
修复数据需可审计脚本、目标预览、事务/分批与结果核对，不直接在生产随手改数。

## 17. 容量与测试数据

容量按日增量×保留期、行/索引/备份/WAL倍数估算。测试使用脱敏或生成数据，标注规模与查询分布。
禁止本地连生产；性能、备份、RLS和迁移验收分别记录在ci-local-rehearsal.md，旧压测和索引比较保留在归档。
