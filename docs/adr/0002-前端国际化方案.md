# ADR-0002：前端国际化（i18n）方案

- 状态：已采纳（2026-11-02）
- 相关代码：`frontend/src/i18n/`、`frontend/src/main.ts`
- 相关规范：`AGENTS.md` 铁律 12「文案一律走 i18n」

## 背景

前端文案目前全部硬编码在 `.vue` 文件里，带来三个问题：

1. 无法切换语言，海外交付需要复制一套页面；
2. 文案与业务逻辑混在一起，页面拆分时反复搬运字符串；
3. 无法做「缺失翻译」检查，新增页面容易漏文案。

## 决策

引入 **`vue-i18n`（Composition API 模式）**，默认 `zh-CN`，`en-US` 作为第二语言骨架。

- 单一入口：`src/i18n/index.ts` 创建 i18n 实例，`main.ts` 统一 `app.use(i18n)`；
- 文案按「模块.场景.键」组织（如 `login.title`、`common.save`），中英文文件 **键集合必须一致**；
- 组件内使用 `useI18n()` 的 `t()`；不在模板里拼字符串；
- 后端返回的错误文案仍直接展示（后端是权威），前端只翻译自己的静态文案。

## 备选方案

| 方案 | 不选原因 |
|---|---|
| 自研 `t()` + 全局字典 | 缺少复数、插值、fallback，后续还得换 |
| 每个页面各自维护文案文件 | 键冲突、无法统一检查缺失 |
| 暂不做 i18n | 违反 AGENTS.md 铁律 12，页面越多迁移成本越高 |

## 影响

- 新增运行时依赖 `vue-i18n`（约 20KB gzip），仅影响前端 bundle；
- 迁移按页面分批进行：先基础设施 + 登录/布局/首页，再逐页替换；
- CI 增加「中英文键集合一致」单测，防止漏翻译；
- 未迁移页面短期仍为硬编码，属已知过渡状态，后续轮次清零。

## 回滚

删除 `app.use(i18n)` 与 `src/i18n/` 即可；组件中的 `t('key')` 会失去注入而报错，
因此回滚需同时还原对应页面（按页面分批迁移可将回滚范围限制在单页）。
