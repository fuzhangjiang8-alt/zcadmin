# 09 · 注释与文档规范

注释解释原因、约束、失败语义和副作用；代码表达显然的操作。行为变更必须同步注释与对应文档。

## 1. 必须写的位置

| 位置 | 内容 |
|---|---|
| 每个源码文件头 | 职责、边界、关键约束；Rust用//!，Vue/TS用注释块 |
| Rust全部pub项 | ///写功能、参数及返回含义、失败语义和副作用；必要时列业务限制 |
| 前端公共类型/函数 | JSDoc写字段契约、单位、范围及使用约束 |
| 非显然逻辑 | 解释事务、权限、并发、缓存、SQL白名单等不能随意更改的原因 |
| SQL迁移 | 目的、兼容性、回滚方式、锁/扫描风险；表与关键列提供COMMENT |
| TODO/FIXME | 负责人/模块、版本或触发条件、现状及替代方案 |

编译器missing_docs检查不能替代内容质量。私有业务转换、状态判断、SQL条件组装也需简洁中文注释。

## 2. 简短示例

```rust
//! 会话替换：负责创建事务，不处理HTTP Cookie。
//! 单端模式按租户/用户串行化，插入失败必须恢复旧会话。

/// 替换指定用户的会话，成功后使本实例缓存失效。
/// 数据库失败则整体回滚；其他实例仍受缓存TTL约束。
// 实际函数签名与实现以源码为准。
```

安全注释应写清可信来源，例如「schema名来自内部常量并经白名单校验」；不能写「已做校验」而省略校验边界。
TODO格式：`// TODO(负责人/模块, 版本): 当前限制；计划替代方式。`

## 3. 不要写

- 逐行翻译、重复函数名、过期状态或无法证实的「已完成/已全绿」。
- 注释掉的代码、裸TODO、用allow(dead_code)掩盖无效实现。
- 口令、token、生产连接串或原始敏感数据。
- 为解释编译失败而长期保留的说明；应修复代码或记录真实阻塞。
- 把完整API/字段/迁移/配置再抄一遍，造成多个真相源。

## 4. 文档分工

| 信息 | 唯一维护位置 |
|---|---|
| 上手与导航 | README |
| 架构目标、决策与代价 | 总览、对应架构章与docs/adr/ |
| 模块职责与函数契约 | 源码文件头、公共项注释；10只提供定位 |
| 部署变量、安全与故障处理 | 05；默认值以config/default.toml和源码为准 |
| 可执行命令与门禁边界 | 07，README只列常用入口 |
| 测试时间、环境、通过/失败和未测项 | ci-local-rehearsal.md |
| 功能规格、领域术语 | specs/、插件CONTEXT.md |
| 阶段总结、技术比较、旧样例和详细历史 | _archive/，不继续追加到规范尾部 |

接口字段以OpenAPI为准、表结构以迁移/schema为准、生成能力以xtask为准。目标必须标「未实现」，历史实测必须有日期，不重复维护易漂移的行数/数量清单。

## 5. 修改后检查

检查源码与文档一致、链接/章节引用有效、Markdown代码块闭合、中文编码正常。规范精简不能删除安全边界、迁移/回滚要求和真实验收限制。
涉及架构决定走ADR评审；文档整理本身不改变架构或放宽AGENTS约束。
