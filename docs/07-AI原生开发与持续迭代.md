# 07 · 开发流程与验收

本文件是可执行命令与门禁边界的集中入口。遵循AGENTS.md；架构/注释分别见01～05和09，实际执行结果只写[验收记录](ci-local-rehearsal.md)。

## 1. 开始之前

读总览、01§4、02§0、09、10及目标插件CONTEXT；插件缺CONTEXT先补。检查工作区改动，不覆盖无关编辑。
当前目录若无.git，明确不能提供Git差异/提交归属；不得初始化仓库或猜历史。字段、状态、接口与配置先查源码/迁移/契约。
新增依赖、存储、安全默认值或架构改变先ADR与人工批准；不把普通实现选择扩大成架构重建。

## 2. 标准工作流

1. **Spec**：目标、验收、涉及表/权限、边界和不做项写入specs。
2. **Plan**：列改动文件、影响范围、风险与必要待确认项。
3. **Generate/Code**：可生成骨架优先生成，遵守生成物边界；小步填业务规则，不一次生成20个文件再验证。
4. **Verify**：针对检查后执行全量门禁；失败定位修复最多3轮，仍失败如实上报，不改断言或跳过失败项。
5. **Review**：重点审领域规则、事务、权限、SQL性能、错误码与恢复路径。

没有匹配生成器不代表可以臆造模板API。新增/修改的方法写必要中文注释，公开项说明参数、失败与副作用。

## 3. 工具实际能力

| 命令（根目录） | 当前作用 |
|---|---|
| `cargo xtask doctor` | 工具链版本、配置文件与DATABASE_URL存在性，不实际测DB/端口 |
| `cargo xtask new-plugin <id>` | 生成插件骨架，挂载/CONTEXT等仍需按产物核对补齐 |
| `cargo xtask gen <schema.toml>` | 生成迁移、Rust模型/CRUD路由并提示挂载；不是完整前后端四层生成器 |
| `cargo xtask openapi` | 正式导出contracts/openapi.json |
| `cargo xtask arch-check` | kernel反向依赖、插件源码互相引用，以及指定业务目录单文件≤300行 |
| `cargo xtask check-perms` | 权限声明/按钮/常量/生成同步与错误码一致性 |
| `cargo xtask verify` | 下列六步验收 |

gen-api、seed、explain-check不是现有xtask命令。行数检查覆盖kernel/src、plugins、server/src及前端views/plugins/features；函数长度、独立unsafe扫描、生成物hash和完整SDK/页面生成不能从该门禁通过推断已覆盖。
生成器旧注释若允许自由修改，不覆盖AGENTS的@generated约束：结构先改schema后正式生成，不手改生成物、dist或.sqlx。

## 4. 常规验收

```bash
cargo xtask verify
```

执行：fmt → clippy -D warnings → cargo test --workspace → 架构边界 → RLS迁移静态覆盖 → 权限/错误码契约。
默认不执行ignored真库测试，不构建前端、不生成契约、不证明浏览器/部署/生产角色隔离。
Windows GNU工具链需MinGW bin在PATH；doctor成功不等于编译器和数据库均可用。

前端（frontend/）：

```bash
npm ci
npm test
npm run typecheck
npm run build
```

build已包含vue-tsc；不必无理由重复检查。当前没有lint脚本，Node内置测试不等于Vitest/Playwright/覆盖率门禁。

## 5. 真库与安全回归

先设置测试DATABASE_URL，禁止指向生产。kernel的sqlx::test自动建/清独立测试库，需要创建数据库权限。

```bash
cargo test -p kernel --test http_contract
cargo test -p kernel --test session_atomicity --test file_atomicity --test user_import_atomicity -- --ignored --test-threads=1
```

server集成测试会在指定库中初始化/改数据，使用专用测试库；共用账号的用例单线程运行：

```bash
cargo test -p server --test smoke -- --ignored --test-threads=1
cargo test -p server --test single_session -- --ignored --test-threads=1
cargo test -p server --test security_baseline -- --ignored --test-threads=1
cargo test -p server --test scope_matrix --test rbac_matrix --test rbac_role --test custom_scope --test tenant_isolation -- --ignored --test-threads=1
```

RLS需按 `.github/workflows/ci.yml` 准备独立的表owner与普通角色，均NOSUPERUSER/NOBYPASSRLS，并明确当前/未来分区授权；随后设置RLS_OWNER_DATABASE_URL、RLS_TEST_DATABASE_URL：

```bash
cargo test -p server --test rls_enforced -- --ignored --test-threads=1
```

不在开发/生产库随意转移表owner。静态RLS通过、超级用户测试及基础sqlx回归均不能代替角色隔离实测。
Webhook真实HTTP、陈旧导出、导入部分成功、性能等其余用例见CI；按改动选择，不把Router测试当网关压力测试。

## 6. 契约与数据库变更

```bash
# 根目录先导出，再进入frontend生成类型
cargo xtask openapi
cd frontend
npm run gen:api
```

检查快照的破坏性变更、权限声明和前后端字段一致性；不能只生成不审阅。新增/改表只增迁移，RLS+FORCE、校验SQL及回滚说明随变更交付；离线SQL元数据按CI要求prepare。
