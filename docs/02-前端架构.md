# 02 · 前端架构

当前是 `frontend/src/` 单包Vue工程。本文说明实际边界；SDK/UI分包、复杂布局与测试平台仅在明确标注处属于目标。命令见[07](07-AI原生开发与持续迭代.md)。

## 0. UI 选型与封装边界

Vue 3.5、TypeScript、Vite、Ant Design Vue 4，使用 `<script setup lang="ts">`，模板/脚本通过vue-tsc严格检查。
既定边界为业务依赖 `@admin/sdk`、`@admin/ui`、`@admin/utils`，组件库只允许UI适配层引用。
当前单包里仍有直接组件库引用，属于待收敛现状，不能据此扩大耦合。沿用既有薄封装，不引入新框架或复制整套管理后台。

## 1. 工程结构

| 位置（frontend/src/） | 职责 |
|---|---|
| `main.ts`、`App.vue`、`router.ts` | 启动、组件/指令注册、静态与插件路由 |
| `views/`、`features/`、`components/` | 页面、领域交互和可复用展示 |
| `api/client.ts`、`api/query-client.ts` | HTTP客户端及唯一共享QueryClient |
| `stores/session.ts`、`directives/perm.ts` | 内存身份、按钮权限 |
| `composables/useDict.ts`、`i18n/` | 字典查询、语言资源 |
| `plugins/`、`types/api.d.ts` | 插件聚合、生成接口类型 |

页面≤300行，复杂表单/弹窗拆features；命名沿用现有PascalCase组件、useXxx组合函数。

## 2. 路由与权限

router守卫先loadSession，再校验路由perm。菜单由服务端按权限下发；插件路由构建期聚合，不是动态下载执行。
v-perm控制按钮，路由控制页面，后端仍校验每个操作及资源归属。403页面不暴露敏感详情。
多页签、keep-alive策略和动态微前端是目标，不假定已有对应store/API。

## 3. 状态管理

| 状态 | 当前存放与规则 |
|---|---|
| 列表、详情、字典、统计 | vue-query；禁止复制进Pinia手动同步 |
| 当前用户与权限 | session.ts的Vue ref，刷新后由/api/auth/me重载 |
| 表单、弹窗等临时交互 | 页面/feature内ref/reactive |

共享QueryClient默认staleTime30秒、retry1、关闭窗口聚焦重取；queryKey包括查询条件，涉及身份的数据不得跨身份复用。
clearSession切换代次并清空用户/在途引用/查询及mutation缓存；旧/me响应和finally不能恢复旧身份或清除新请求。
退出须服务端撤销成功才清身份跳登录；失败保留页面提示重试。重新登录成功也先清旧缓存再进入守卫。

## 4. 字典与国际化

useDict按需查询，返回items/loading/labelOf；loadDict复用相同配置，键为 `['system-dict', code]`，staleTime为Infinity，缓存仍可能被GC或显式清理。
字典不写localStorage、不做版本比对；queryFn转交AbortSignal，切身份后旧请求不可回填。clearDictCache只移除字典查询。

所有用户文案走vue-i18n，中英文键一致。禁止模板/脚本硬编码中文；服务端错误内容按现有契约展示，前端通用提示使用词条。

## 5. 请求层

入口为 `request<T>(path, init)` 及http便捷方法，位于api/client.ts。

| 情况 | 当前行为 |
|---|---|
| 请求 | credentials=include；支持Headers/元组/对象，保留调用方请求头 |
| body | 字符串默认JSON；FormData交浏览器生成boundary，不手写Content-Type |
| 成功 | 解包data，204返回undefined；缺少data或异常成功体显式失败 |
| 错误 | problem转ApiError(code/message/status)；HTML/纯文本/空体保留HTTP状态，不展示代理HTML |
| 取消 | 转交AbortSignal；组件/查询负责生命周期 |

当前没有令牌refresh、自动重放、统一503退避或全局请求超时；由页面处理异常。vue-query的查询retry不等于写接口重试。
429/503语义见后端文档；不得自动重试非幂等操作。

## 6. 类型契约

后端先导出contracts/openapi.json，再用npm run gen:api生成types/api.d.ts，禁止手改。
前端字段、可空性和错误码跟随契约，不自行猜测接口。版本/破坏性变更按01规范评审。

## 7. 组件与交互

- 通用组件只负责展示/交互；请求和路由由feature/页面编排，避免巨型万能组件。
- 表格保留稳定rowKey，分页/筛选/加载/空态/错误态清晰；写入成功按queryKey失效相关缓存。
- 表单校验在提交前提示；提交期间防重复点击，删除/批量危险操作需明确确认和结果反馈。
- 使用共享样式/设计token；权限、禁用、加载状态有语义，不能只改颜色表达。
- 保留键盘操作、焦点、表单标签、错误关联与合理对比度；对目标视口单独验收。

ProTable、SchemaForm、统一主题/页签平台未全面落地，新增抽象需结合真实复用，禁止为一页引入庞大配置层。

## 8. 性能与安全

路由懒加载、按需注册组件、稳定queryKey并避免重复请求。构建分包由vite.config.ts管理，包体/首屏目标见总览，不能把构建通过当性能达标。
禁止localStorage存token、前端写密钥或任意v-html渲染；URL、下载及外链保留授权和来源边界。
WebSocket/SSE、预签名/分片、离线缓存、动态微前端都需真实后端协议，不能按旧设计示例直接使用。

## 9. 测试与交付

当前npm test使用Node内置runner与类型擦除，覆盖HTTP、身份/字典竞态、权限和i18n；build包含vue-tsc与Vite。
Vitest、组件测试、Playwright、MSW、覆盖率门禁及通用lint工具未全面配置，不得声称已通过。
浏览器交互、视觉/视口及生产构建分别验收。实际测试数字和日期只维护在[验收记录](ci-local-rehearsal.md)。

## 10. 前端插件注册表

`src/plugins/index.ts` 聚合各插件声明，再展开routes与i18n；插件只访问公共契约，不直接读取其他插件store或互相import。
新插件按[04插件体系](04-插件体系.md)接入；Module Federation和独立前端包为后续方案，本轮不更换既有选型。
