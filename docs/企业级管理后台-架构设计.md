## 1. 范围与优先级

内核负责身份、组织/RBAC、租户、审计、文件、配置与运行基础设施；业务归各插件。
取舍顺序为：安全 → 正确性 → 可用性 → 性能 → 开发效率。
不自研 BPMN、报表引擎或消息中间件，不做 dylib 热插拔；复杂流程对接外部系统。

## 2. 非功能需求（NFR）

以下沿用既有目标，须以实际测试或演练证明，修改目标需评审。

| 维度 | 目标 |
|---|---|
| 负载 | 500 在线操作员，峰值 1000 QPS，读写比 8:2 |
| 延迟 | 列表/详情 P95 < 200ms、P99 < 500ms；聚合报表异步 |
| 前端 | 内网首屏 < 1.5s、路由切换 < 300ms |
| 可用性 | 单机房 99.9%，主备 99.95% |
| 恢复 | RPO ≤ 5min、RTO ≤ 30min，季度恢复演练 |
| 规模 | 单表 ≤ 1 亿行；审计年增 ≤ 5 亿行并按月分区；单集群 ≤ 1000 租户、单租户 ≤ 5 万用户 |
| 审计 | 登录/操作日志至少 6 个月，可归档 3 年 |
| 发布 | 灰度 10% → 50% → 100%，5 分钟内可回滚 |
| 安全与兼容 | 等保三级/OWASP 基线；N-1 API 兼容 ≥ 6 个月；Chrome/Edge 最近两个大版本 |
| 可维护 | 单插件目标 ≤ 3 万行，新增插件不修改内核实现 |

现有 25 并发 Router::oneshot 基线不经过 TCP，不能证明上述容量。灰度、灾备、安全测评和浏览器性能均需独立验收。

## 3. 总体架构与依赖

```text
Vue / Tauri / Flutter → 网关 → apps/server → kernel + plugins → PostgreSQL
```

- 模块化单体、编译期插件；PG 是唯一持久化真相源，缓存不能代替数据库。
- `apps/server` 装配内核和插件；插件依赖 kernel，kernel 不得反向依赖业务插件。
- 插件禁止直接引用其他插件；跨域协作通过事件/公共契约，未经评审不新增直接跨表耦合。
- 当前使用显式组合根 `AppState`；前端是单包 Vue 工程，未来包边界不应写成已实现。
- 私有化以单机/容器交付为起点；多副本、PG 主备及其他存储按负载与运维能力演进。

保留旧编号以便查历史，不把设计决策误写成现有能力。

## 5. 环境与演进

local 用开发库；CI 用临时库；测试用脱敏数据；staging 用生产同构拓扑；生产只接受流水线变更。
禁止本地直连生产库，生产导出必须授权、脱敏、审计。

先保证基础闭环与一个业务域，再按实际复用补平台能力。新增依赖、存储、服务拆分及安全默认值需 ADR 与人工评审。
