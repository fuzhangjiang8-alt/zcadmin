# 01 · 后端架构

本文规定运行时、分层及接口边界。模块定位见[代码地图](10-后端代码地图.md)，命令见[开发流程](07-AI原生开发与持续迭代.md)，配置与上线见[运维](05-安全合规与运维.md)。

## 1. 进程模型与运行时

### 1.1 线程模型

Tokio worker 只执行异步 I/O 与短逻辑。Argon2、Excel、图片和同步文件操作走 `kernel::blocking::run`；工作簿构造走 `kernel::xlsx::run` / `run_anyhow`。
默认受控并发4、排队超时3秒返回503。禁止直接 `spawn_blocking` 绕过并发限制。后台维护目前用 spawn + interval，任务必须幂等并说明多实例行为。

### 1.2 优雅停机

入口 `apps/server/src/main.rs`：not-ready → 摘流缓冲3秒 → 排空 → 关闭池/刷新追踪 → 退出。
默认排空20秒，watchdog防无限等待；编排终止宽限必须大于排空+3秒，compose默认40秒。
Windows检查不能代替Linux SIGTERM、滚动发布和事务完整性演练。

### 1.3 超时预算

默认请求30秒、SQL5秒、取连接5秒；网关预算大于请求，SQL与取连接均非零且分别小于请求，启动时校验。
TimeoutLayer不覆盖响应体传输，慢下载仍需网关兜底。外部HTTP须有连接/总超时与重试上限，禁止在事务内等待外部请求。

## 2. Workspace 与依赖方向

`apps/server → plugins/* → kernel`；kernel不依赖插件，插件不直接互相use。共享类型、错误和状态放kernel。
沿用工作区Rust版本与依赖，不为局部需求升级框架；新增依赖须ADR批准。

## 3. 请求生命周期

### 3.1 中间件顺序

以 `crates/kernel/src/app.rs` 为准，Axum后加layer在外层。当前请求路径：

```text
请求体上限/安全头 → ClientIp → CSRF → CORS → 压缩 → 指标
→ RequestId → Trace → CatchPanic → 过载/并发限制 → 请求超时 → 路由
```

安全头覆盖拒绝响应；ClientMeta先于限流/审计；过载快速拒绝。CatchPanic依赖 `panic = "unwind"`，禁止改为abort。
默认body上限2MiB，上传/导入单独调整；改装配、启动或停机顺序必须同步本文和测试。

### 3.1.1 客户端IP与可信代理

默认只信TCP对端；仅当其属于trusted_proxies时从右向左解析转发链，选第一个不可信地址。生产入口必须提供ConnectInfo；禁止业务自行选择请求头绕过此边界。

### 3.2 提取器

CurrentUser解析身份与权限；TenantTx开事务并注入事务级tenant/user；查询使用现有提取器。
客户端IP只取ClientMeta：默认TCP对端，仅可信代理可解析转发链。禁止handler直接读XFF/X-Real-IP。

## 4. 分层规范

| 层 | 职责 | 禁止 |
|---|---|---|
| handler/api | HTTP解析、参数校验、调用服务、响应转换 | SQL、复杂业务分支、隐式事务 |
| service | 业务规则、事务、跨repo编排 | 依赖Cookie/HTTP状态 |
| repository | 参数化SQL、分页、权限条件、映射 | 业务决策、跨插件写入 |
| domain | 实体、值对象、状态约束 | 依赖HTTP/数据库运行时 |

现有内核仍有handler/read直接执行SQL，是待收敛差距；新功能遵循分层，不做无关全量重构。
DTO与实体分离，禁止暴露敏感字段。函数目标≤50行、文件≤300行，注释按09。

## 5. 事务与并发

- service显式管理事务；TenantTx使用 `set_config(..., true)`，禁止会话级租户配置回池串租户。
- 乐观锁在WHERE校验版本并处理零影响行；唯一性用数据库约束兜底，不能只先查再写。
- 单端登录同事务按tenant/user获取咨询锁，再删旧会话、插入新会话；插入失败整体回滚。
- 用户导入逐行SAVEPOINT，SQL异常只回滚该行，成功行最终一次提交；dryRun不写用户。
- 重试、任务抢占、幂等与补偿须覆盖重复请求和多实例。通用幂等/Outbox框架尚未实现。

## 6. 错误模型

成功通常使用ApiResponse/ApiResult；文件内容保留正确HTTP语义。错误使用AppError → `application/problem+json`，字段为type/title/status/code/detail。

| 情况 | 状态 |
|---|---|
| 未认证 / 无功能权限 / 不存在或资源越权 | 401 / 403 / 404 |
| 冲突 / 参数无效 / 限流 | 409 / 422 / 429 |
| 过载、连接池获取超时或关闭 | 503 |
| 其他SQL或内部异常 | 500 |

5xx细节只写日志，不回显SQL、路径、堆栈；稳定错误码只追加并同步 `contracts/errors.json`。
429/503带Retry-After：通用错误5秒，登录限流60秒；不意味着客户端自动重放写请求。

## 7. 校验与入参安全

DTO显式列可写字段，校验长度、枚举、金额和body。SQL值用绑定参数，表名/排序只能取内部白名单。
size归一化1..200，极大page的OFFSET饱和到i64上限。用户可控出站URL还需SSRF与网络限制，见05。

## 8. API 契约规范

沿用模块路由、参数与返回结构，权限点为 `{plugin}:{resource}:{action}`；写接口必须校验且声明权限。
OpenAPI注解是契约源，改接口后正式导出并生成TS；删除字段、改类型/必填等破坏性变更须升版或宽限期。
以response.rs和实际契约为准，不从目标示例臆造traceId、过滤DSL、刷新或任务接口。

## 9. 认证与会话

### 9.1 登录

数据库用户+Argon2id；不存在/锁定分支保留时序防护。初始账号配置只作用于空库，强制改密及策略按租户规则处理。
令牌通过HttpOnly Cookie返回，DB仅存SHA-256。PAT形如 `zc.{tenant}.{secret}`，scope收窄不能恢复平台超管权限。

### 9.2 会话与刷新

默认有效期8小时；缓存TTL30秒、上限10000项，代次防旧查询回填。写操作只失效本实例，其他实例仍有TTL窗口。
退出撤销失败不能返回假成功，成功后才过期Cookie。Refresh轮换、MFA、空闲超时、敏感操作二次票据尚未实现。

### 9.3 CSRF 防护

POST/PUT/PATCH/DELETE校验Sec-Fetch-Site/Origin；无来源头的非浏览器调用仍受认证/权限约束。
当前不是双提交token方案；部署需核对代理、Host与CORS，禁止扩大白名单掩盖问题。

## 10. 授权

功能权限、租户隔离、数据范围独立校验；隐藏按钮不替代鉴权，资源越权返回404。
范围条件复用scope::condition，覆盖all/dept/dept_and_child/self/custom，多角色规则由实现和矩阵测试确定。
平台超管不等于租户管理员，带scope的PAT不能冒充平台通配身份。

## 11. 多租户运行时

会话/PAT确定tenant，TenantTx设置上下文；跨租户平台能力显式鉴权。停用/删除租户同步撤销会话，配额在服务端执行。
RLS需FORCE且使用NOSUPERUSER/NOBYPASSRLS角色；表owner和普通角色都须真库验证。

## 12. 缓存

DB是唯一真相源。缓存键/失效体现租户与身份，清理后旧请求不得回填；前端切身份同时清查询/字典缓存。
跨实例强失效另行评审，短TTL不能称为全局即时撤销。避免无界增长与并发回源尖峰。

## 13. 领域事件与 Outbox

目标：业务落库与事件入箱同事务，至少一次投递、消费者幂等、重试/死信/重放可观测。
当前无通用Outbox/EventBus实现；跨插件新协作先明确契约和落地方式，不调用旧示例中的虚构API。

## 14. 任务调度

当前维护任务为interval；持久化调度、租约、进度、补偿是演进目标。新增任务必须有超时、失败日志、幂等及多实例/停机说明。

## 15. 文件与导入导出

- 本地存储key由服务端生成并防路径穿越，DB存元数据；默认单文件20MiB，接口body限制分别生效。
- 下载鉴权后释放只读事务再读盘，仍全量读内存；无通用预签名/Range/分片能力。
- 删除先提交软删再删内容；提交失败保留原文件；物理删除失败留日志和storage_key，自动重试清理未实现。
- 用户同步导入最多500行、body 10MiB；模板/错误报告走受控池，报告最多500行且不含初始密码。
- 异步导出有状态和20000行上限，需处理失败/陈旧任务；部分生成/落盘路径仍持事务。大批量、流式、病毒扫描属后续能力。

## 16. 插件运行时

### 16.1 启动与启停

契约与装配只维护在[04插件体系](04-插件体系.md)。迁移失败使启动失败，禁用不删除已有数据。

### 16.2 失败策略

panic隔离不是CPU/内存/安全沙箱；通用on_start/on_stop及热装尚未实现。
CatchPanic把当前请求panic转成500，进程继续服务，必须保持unwind；不可把插件迁移失败降级成带未知结构继续运行。

## 17. 可观测埋点

Tracing、RequestId、指标、审计分别负责链路、定位、容量和业务行为；不得记录口令/token/原始敏感体。
默认采样0.1，错误/慢请求100%采样尚未实现；指标访问与告警配置见05。

## 18. 性能与容量

按实例数×池上限及后台/运维核算连接，监控等待与慢查询，避免N+1、无界聚合和长事务。
网关压测、故障注入与恢复演练前不得宣称达到NFR；旧基线数据保留在历史归档。

## 19. 测试策略

覆盖正常/参数异常、无权限、跨租户、并发、重复提交和回滚。事务需真实数据库约束验证，不能只用Mock。
命令与门禁边界见07；执行日期、环境和结果只写[验收记录](ci-local-rehearsal.md)。

## 20. 后端反模式清单

禁止改已发布迁移、手改生成物、吞错、无上限重试、事务内外部HTTP、跨插件直接依赖、泄漏anyhow、unsafe及非测试unwrap/expect。
行为与注释同步，其余贡献要求遵循AGENTS.md。
