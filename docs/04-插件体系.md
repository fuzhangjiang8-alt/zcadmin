# 04 · 插件体系

本文说明接入契约与隔离要求，不维护各插件业务字段/功能流水账。领域细节以插件CONTEXT.md、迁移与OpenAPI为准。

## 1. 扩展形态

当前为Rust crate + trait + inventory的编译期插件，升级需重新构建发布；不支持dylib热插拔或运行时下载代码。
独立服务、微前端及WASM只有在06中的条件满足并完成评审后引入。

## 2. 当前契约

唯一真实定义在 `crates/kernel/src/plugin.rs`。

| 类型/方法 | 职责 |
|---|---|
| PluginMeta | id、name、version、depends_on、order |
| Plugin::meta | 必须提供元信息 |
| migrations | 可选静态Migrator |
| routes | Router<AppState>，装配到/api/{id} |
| permissions / menus | 权限与菜单声明，启动期幂等同步 |
| openapi | 可选契约片段 |
| PluginRegistration::create | inventory注册构造函数，内核不感知具体类型 |

id发布后不可改，只用小写字母/数字/下划线。schema等于id，权限前缀与路由应一致。
旧文档里的PluginCtx、perms!/menu!、dicts/jobs/config_schema、on_start/on_stop等不是当前可用API，不可照抄。

## 3. 装配与启停

```text
读取启用配置 → inventory收集/过滤 → 校验与拓扑排序
→ 内核及插件迁移 → 同步权限/菜单 → 挂路由 → 服务就绪
```

缺依赖、成环或迁移失败阻止启动。依赖元信息不授权插件直接use其他插件。
目前支持两层裁剪：

| 层 | 入口 | 行为 |
|---|---|---|
| 编译期 | apps/server的Cargo features | 裁剪未启用crate，默认集合以Cargo.toml为准 |
| 运行期 | DISABLED_PLUGINS逗号分隔 | 启动时不迁移/同步/挂载被禁用插件 |

启用插件依赖被禁用插件时启动失败。禁用不是卸载，不删除schema/数据；修改配置后需重启，不是运行中热切换。

## 4. 数据与运行隔离

- kernel不依赖插件，插件不互相use；新增跨域协作走已批准契约/事件。
- 只写本域schema，tenant表具备策略与FORCE；TenantTx使用事务级上下文。
- 重CPU/内存任务走blocking/xlsx受控池；外部请求不放数据库事务。
- 权限、范围、审计、错误和body限制复用内核；不能靠前端隐藏按钮鉴权。
- 禁止进程exit、无限线程/循环、全局可变状态或不受控重试。

同进程插件不是资源/安全沙箱，CatchPanic也不能隔离OOM或恶意代码。需要独立资源故障域时评估服务型扩展。

## 5. 前端接入

当前 `frontend/src/plugins/` 构建期聚合routes/i18n等声明；菜单由后端同步并按权限下发。
组件使用scoped或命名空间样式，不污染宿主；不访问其他插件store或直接互相import。
业务只依赖公共SDK/UI边界，已有单包结构按02逐步收敛，不借接插件扩大组件库耦合。

## 6. 新增与修改流程

1. 先写规格和CONTEXT.md：术语、表、权限、状态、事件、边界与不做项。
2. 参考plugins/demo及当前Plugin trait；脚手架入口、实际生成范围和验证命令见07。
3. 在server依赖/features及显式链接处接入，保持前端注册与后端启用一致。
4. 补迁移/RLS、权限/菜单、接口注解、i18n及集成回归；有生成物必须改schema后正式生成。
5. 检查禁用、缺依赖、重复注册、越权、跨租户与迁移失败路径，再交领域评审。

不在本文复制完整插件实现，以免与黄金样例及生成器漂移。

## 7. 导入导出注册

`imports::ImportRegistration` 和 `exports::ExportRegistration` 用inventory注册类型、权限及执行函数；字段以源码为准。
内核统一路由/鉴权/任务与事务入口，插件负责本域解析、查询和写入。必须明确行数/body上限、部分成功/回滚、数据范围与日志脱敏。
Workbook构造和解析必须受控执行，不能因为在后台tokio::spawn就直接运行同步重任务。

## 8. 版本、交付与退役

公共Plugin trait/API破坏性变更需版本/兼容策略及所有插件影响评估。依赖版本、启用集合、迁移与契约随同一制品交付。
退役先停止新增使用、确认依赖/权限入口、归档/迁移数据，再计划删代码/schema；运行期禁用不承担数据退役职责。
插件负责人维护CONTEXT和验收证据。完整注册中心、签名分发、多版本热切换及运行期熔断属于目标，不能视作已实现。
